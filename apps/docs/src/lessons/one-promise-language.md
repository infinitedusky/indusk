# One Promise Language — Lessons

**A stored value changes reader-first, writers a release later.** Renaming
`violated` to `broken` in one release would have made every recording server
older than the plan drop the signal, and the promise would go dark. Every
reader learned both words first, through one `readOutcome`; the writers keep
`violated` until `mark-first`, the next release. Words people read change in
one step; values programs read do not.

**"Machine-read" is wider than the obvious wire.** The decision applied that
rule to the signal attribute and missed `indusk promises health --json`, which
the installed editor reads and `indusk update` never refreshes: an editor from
before the release read every `broken` run as held. A fresh review found it by
asking which programs read each changed value. Ask that in research, for every
value — attributes, `--json` output, states written into files.

**A word scan proves only the patterns it lists.** The first scan refused
*the mark* and let *production marks* and *sends marks* through. A vocabulary
guard needs a reader trying the senses it does not list.

**A new look needs its page to report its state.** The approved
`promise-row.no-signal` look came back unchecked — not broken — until the
promise list reported that row's state to the looks check. Silence there is
not a pass.

**What we'd do differently.** Put the plan's own clauses against every surface
in the brief: the dashboard's green dot for a promise nothing had reported
contradicted "no signal is never shown as holding", and only the review saw it.
