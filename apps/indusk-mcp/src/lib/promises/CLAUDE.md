# lib/promises — rules for working here

Loaded by Claude Code when a file under `src/lib/promises/` is read. Moved here
from the package `CLAUDE.md` on 2026-10-10 (release-records-its-failures): they
apply to this folder only.

- One registry subpath (`promises/registry`) for CLI, MCP and admin; writes
  only via `lib/promises/write.ts`; marks through `readPromiseMarks` and
  `jaegerEndpoint`; unreachable = exit 2, never zero. `promises.jaeger`
  (`url` + `credential_env`, a variable's *name*) names a server; absence =
  the local daemon. — see `/decisions/day-monitor`
- **An opened incident never takes an id its owner's Maintenance phases name**
  (`maintenanceIncidentIds`); `watch` exits 1 for, and retries every run,
  any incident left without its owner's phase. Evidence: `traces:` or
  `tests:`+`release:` (a release's incident is written by `test-incident.ts`, never imported by `release/`); readers take both. — see `/reference/cli/promises`
- **`recordBreaks` is the one writer, run by the admin unasked; it commits on a trunk only**, after the inbox and heard rows;
  what it could not commit waits in the home's `pending-commit.json`. — see `/decisions/incident-recording`
- **A plan's dates fall back for what older plans never wrote** (`display.ts`):
  an archived plan is landed on its retrospective's `date` (else its impl's),
  and `started` is the first lifecycle document's `date` when there is no brief.
  — see `/reference/cli/promises`
- **The release that shipped a plan is the first `chore(release):` commit after its landing, never a changelog pattern; a plan's landing date has one function** (`landedDate` in `display.ts`; `closedAt` delegates) — a second reader of the "Landed on main at" line fails `display-names-single-definition.test.ts`. The trunk is read by one `git log` per `readHealthNames` call; the changelog is only the no-release-commits fallback. — see `/reference/cli/promises`
- **`display.ts` reads a plan document's frontmatter through `gray-matter`, never its own pattern** — the plan page and the editor must name one plan one way; a date YAML parses to a `Date` is turned back into `YYYY-MM-DD`. — see `/reference/cli/promises`
- **Always-on server (Day 4b′), moved from the root at plan-cockpit's close:** the shipped Jaeger as a server (badger + basic auth, Fly reference); an in-process pass announces each violation once to Slack, failure-safe; detect-and-notify only; a project names its Jaeger, absence = local — see `/decisions/day-always-on`; deployed and smoked on Fly — `/decisions/day-always-on-deploy`
- **The dashboard's thirty days and a promise page's are one function's, never two** (`standing.ts`'s `dayCounts` over thirty UTC days ending today): held is days with an upheld run and no break, broken is days with a violation heard, an unwatched day is neither; a second counter fails A5 in `proof.test.ts`. — see `/reference/admin-ui/promise-page`
- **Watcher heartbeat, moved from the root at cockpit-redraw's close:** every promise read first probes its Jaeger (a span sent and read back) and says *watcher blind*, never zero; the server beats each pass and tells Slack once each way — see `/decisions/watcher-heartbeat`
- **A signal's outcome is read only through `readOutcome`** (`vocabulary.ts`) — `broken` and `violated` both mean broken, so applications instrumented before 2026-10-15 keep working; `markPromise` writes `broken`. The registry reads `known-violated` as `known-broken` (`readPromiseState`) and never rewrites it. — `promise: a-promise-is-upheld-or-broken`, see `/decisions/one-promise-language`
- **`promises health --json` is a wire: its `runs[].outcome` stays `violated` for a break until `mark-first` switches every writer** (`health-line.ts`), because an installed editor is not updated with the package and reads `violated` as broke. — `promise: a-promise-is-upheld-or-broken`
- **An app's signal and resource keys live in `vocabulary.ts` (`APP_SIGNAL_KEYS`, `APP_RESOURCE_KEYS`); `templates/signal.ts`, `signal.py`, `telemetry-settings.ts` and `instrumentation.py` spell them as strings and `signal-vocabulary-pin.test.ts` holds them equal — change both sides together.** — see `/reference/telemetry/signal-helper`
- **A signal names its promise and clause, writes `broken`, and a span made under a test runner carries `indusk.run=test`, which no reader counts — on the span or on its resource (process tags)** (`markPromise`, `parseMarkedSpan`): a test's passing never stands in for a clause's signal. A test that round-trips a writer through the reader clears `VITEST` first. `parseMarkedSpan` takes a break's plan and phase from its event, else from the span (the app helper's way), and `indusk.signal.value`/`bound` only as numbers; both travel on `MarkedSpan` and the timeline mark into every `ClauseReport` (`reportsOfClause` is the one mapping from a daemon read), so a limit measured past its bound reads broken. — guarded by `signal-test-run.test.ts`, `clause-measured.test.ts`, `promise: a-clause-is-proved-twice`
- **A clause reads from its own signal, one reader: `clauseStanding` (`clause-standing.ts`, re-exported by `standing.ts`)** — holding only on a real report with a live watcher, `no signal` when nothing reported or the watcher is blind (never drawn as holding), broken on a break (a split by its newest report, a limit by any one); passing tests are not an input. A promise is its worst clause (`promiseSignal`), a resting clause reads as the promise it rests on; `readsSignal` is the one rule for which promises telemetry is read for (behaviour, or any with split/limit clauses). `promises status`, the promise page's proof and the admin all take it from `readStanding`/`clauseStanding`, never a second computation. — guarded by `clause-standing.test.ts`, `promise: a-clause-is-proved-twice`
- **Closing a plan with `clauses: required` reads the system, not its State cells: it runs each split and limit clause's tests now and asks the local daemon for its signal, both handed in (`runTests`, `readSignals` on `confirmPlan`; the halves in `clause-proof.ts`, the real ones in `closing-inputs.ts`)** — a refusal names `promise/clause` and which half is missing; a stopped daemon refuses, never passes; a plan given neither input is refused. Landing runs the same tests half (`refuseFailingClauseTests`), never the signal. A plan without `clauses: required` keeps the old rule. A clause test that asserts nothing — no `expect(`/`assert(` call outside comments and imports — is refused, and so is one whose every test was skipped (`runFiles`'s `ranNoTest`; "ran no test (skipped)"); a promise made only of resting clauses needs no row, test or site of its own (`restsOnly`). `promises status` writes `no-signal-is-not-holding` from the clauses it shows (`status-signal.ts`). — guarded by `clause-tests-run.test.ts`, `confirm-signal.test.ts`, `land-clause-tests.test.ts`, `confirm-legacy-plan.test.ts`, `clause-test-runner.test.ts`, `status-signal.test.ts`, `promise: a-clause-is-proved-twice`
- **An incident is keyed by `promise/clause`; the plan and phase that added the signal are a pointer, second** (`incidentText`, `provenBy` in `incidents.ts`): `recordViolations` groups a pass's breaks by clause and matches an open incident on promise and clause, so a second clause's break opens its own incident, never extending the first's; a break that names a clause writes `clause:` in the frontmatter and a Signal line, lists only the rows that prove that clause and the `sites` that emit it, and `watch` reads every promise `readsSignal` (not only behaviour). A promise with no clause writes the incident it always did. The recorder writes the verdict on each incident it opens from a clause's break (`incident-signal.ts`). — guarded by `incident-names-clause.test.ts`, `incident-no-clause.test.ts`, `record-clause-break.test.ts`, `incident-per-clause.test.ts`, `promise: a-clause-is-proved-twice`
