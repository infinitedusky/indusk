# dusk — Project Context

## What This Is

A pnpm + Turborepo monorepo containing the InDusk development system. The repo dogfoods its own skill system — the same plan/work/verify/claude-md skills used to build features are also the product being showcased.

## Architecture

```
dusk/
├── apps/
│   ├── indusk-mcp/        # InDusk MCP server — CLI, skills, hooks, lessons, extensions
│   ├── indusk-admin/      # Next.js read-only admin UI (daemon via `indusk ui`)
│   └── docs/              # VitePress docs site (guide / reference / decisions / lessons)
├── packages/              # telemetry-binaries-* — platform-split jaeger + otelcol
├── .claude/skills/        # Installed skills — package-owned, synced from apps/indusk-mcp/skills/
├── .claude/lessons/       # Lessons registry — titles are the rules; bodies load on demand
├── docker/                # Dockerfiles (Dockerfile.infra retired by indusk-makeover)
├── biome.json             # Quality ratchet — see biome-rationale.md for per-rule why
├── vitest.config.ts       # Workspace projects; apps inherit via extends
├── .indusk/               # InDusk home — planning/, extensions/, config.json, current.md
└── CLAUDE.md              # This file — living project memory (60 KB budget, hook-enforced)
```

**Apps:**

- **indusk-mcp** — the InDusk MCP server + CLI (`init`/`update`/`setup`/`extensions`/`agent`/`plans`/`sync`/`context`/`eval`/`ui`/`telemetry`/`worktree`). Published as `@infinitedusky/indusk-mcp`. Skills in `apps/indusk-mcp/skills/*.md` sync to consumers' `.claude/skills/` on init/update (globSync, both sides). Hooks in `apps/indusk-mcp/hooks/*.js` install to `.claude/hooks/`. Git is the only SCM (1.31.0); commit IDs via `apps/indusk-mcp/src/lib/scm/index.ts`. Retired MCP servers are removed via the shared `apps/indusk-mcp/src/lib/mcp-migration.ts` helper (init + update both call it) — extend `LEGACY_MCP_SERVERS` on future retirements, never hand-roll a removal loop. The `doppler` extension is the default env layer (per-worktree auto-provisioning); composable.env is deprecated opt-in.
- **`indusk run <plan> --model <name>`** (Dawn external orchestrator, `apps/indusk-mcp/src/lib/run/`) — plan phases through a model-agnostic gated AI-SDK loop: per-phase scope, advance-on-green via a deliberate `check-gates` probe, goalpost guard, human-gate pause; direct provider keys via the registry. Gate chain is three shared scripts (`validate-impl-structure` → `check-gates` → `claude-md-budget`); `gate-reminder` deliberately shed (dawn-hook-parity ADR). The loop commits per checklist item (loop-owned, intent-derived messages; failures loud-but-non-gating; non-git worktrees disable cadence loudly). **`ask` is the default policy in both lanes** — a headless proof-less gate skip pauses (exit 3) with the question rather than red-stopping; `auto` is an explicit per-plan opt-in. **Two roots in a one-repo workbench** (`resolveExecutionRoots`, before the provider-key check): the loop edits, runs bash and commits code in the code root and reads the impl, resolves the gate scripts, runs every envelope (`cwd` = plan root) and commits checkoffs in the plan root; `resolveInRoots` (`lib/run/worktree-paths.ts`) is the one confinement rule — inside the code root or inside `.indusk/planning/<plan>/`, nothing else, refusal naming both. Two commit cadences, one per repo; the plan-side checkoff commit carries `Code-Commit: <code HEAD>` and is never queued for eval. Zero or several declared repos still refuse by name. — see `/reference/cli/run`
- **`indusk verify <plan> --phase N`** (Dawn component 6, `apps/indusk-mcp/src/lib/verify/`) — phase-boundary verification for work Dawn did **not** execute (tier 3, where there is no hook seam). Five detections: premature checkoff + skipped test-first duty (the former via `probePhaseClose`, the latter applied to phase N **directly** — the probe asks about N+1 and neutralizes its rows, so the verified phase's own duty is invisible to it), goalpost drift (`checkGoalposts` vs `git show <baseline>:impl.md`), red tests, phantom work. **Detects and reports; never repairs** — reverting is component 7's, and `git reset` cannot un-write a working tree. Baseline comes from the chained ledger `.indusk/verify/ledger.jsonl` (`merge=union`), bootstrapping from the merge base. — see `/reference/cli/verify`
- **indusk-admin** — Next.js App Router read-only viewer over `.indusk/planning/` + `.indusk/eval/`, hosted as a single machine-global daemon (`indusk ui start/stop/restart/status`, registry `~/.indusk/projects.json`, routes `/p/[project]/...`). Custom Tailwind primitives (no shadcn/Radix); reuses indusk-mcp parsers via workspace subpath exports — never duplicate parsing. Bundled pre-built into the tarball by `prepublishOnly` (`apps/indusk-mcp/scripts/bundle-admin.js`). The plan page is live: `LiveRefresh` probes the page and `router.refresh()`es every `admin.refresh_ms` (default 5000), pauses when hidden, stops visibly on failure; no other page polls. — see `/decisions/admin-ui-hosting` + `/reference/admin-ui/overview`
- **docs** — VitePress site. Every plan contributes pages at close (decisions/lessons/reference); ADRs publish to `/decisions/*`.

**MCP servers** (project `.mcp.json` keep-list, indusk-makeover): **indusk** (dev-system tools), **dash0** (hosted observability; `Authorization: Bearer ${DASH0_AUTH_TOKEN}` — token lives in `~/.indusk/config.env`, never committed), **jaeger** (local-telemetry daemon's MCP — critical), **posthog**. Global keep-list: **playwright** only. Graphiti + codegraphcontext are retired — `init`/`update` remove stale registrations. — see `.indusk/planning/archive/indusk-makeover/adr.md`

**Skills** (process): planner, work, verify, claude-md (was `context` — shadowed by Claude Code's built-in `/context`), document, retrospective, catchup, handoff, falsify, cleanup, highlight, rail-check, git, eval-review, toolbelt, **write** (a writing session's catchup + voice + review passes + publish; prose only, no gates — see `/reference/skills/write`). Each concept has one canonical skill; edit in `apps/indusk-mcp/skills/`, never `.claude/skills/` directly.

**`/work`'s per-phase order gains Shape between Verification and Context** (`apps/indusk-mcp/src/lib/shape/`) — craft review of the code *that phase* wrote, against the enabled extensions' prose rules. It is a **step, not a gate type**: no `#### Phase N Shape` heading, no validator rule, nothing retrofitted into the 51 existing impls (gate vocab is closed in 4 sites and an unknown heading fails *silently*, misclassifying its items). The executing agent performs the judgment — it is already a model, so no extra call — while the library supplies only facts: `changedFilesForPhase` (scoped by a generic `{plan, phase, sha, at}` boundary record written at phase start, `.indusk/` excluded), `collectCraftRules`, and three writers that all route through one `appendItemToPhase`. Findings land as unchecked implementation items in the current phase, so existing gate machinery makes them non-ignorable without Shape blocking anything. — see `/guide/shape`

**Agent roles** (three tiers — see `.indusk/planning/archive/agent-roles/adr.md`): the **working agent** does the user's task and flags moments via `mcp__indusk__highlight`; the **eval agent** (background, fires on `git commit` + session end) scores work and materializes durable highlights into **lessons** via `add_lesson` (indusk-makeover retargeted it from Graphiti); **infrastructure** (hooks, CLI, validators) enforces invariants. The working agent never materializes highlights itself.

## Conventions

- pnpm workspaces + Turborepo; **Node 22 required** (Tailwind 4 native bindings).
- **Biome, not ESLint** — `pnpm check` / `pnpm check:fix` / `pnpm format`. Biome config is a knowledge artifact (`biome-rationale.md`); the ratchet only tightens. After each retrospective ask if a mistake could become a Biome rule.
- `pnpm test` runs all; `pnpm turbo test --filter={app}` scopes. Vitest `passWithNoTests: true` must be set per-app (root `extends: true` doesn't inherit it).
- **CLAUDE.md has a hard 60 KB budget enforced at write time** — `claude-md-budget.js` PreToolUse hook blocks past `context.claude_md_budget_bytes` (61440 default; warns at 90%). Entries are 1–3-line rules + pointer. Compact, don't grow; raise the budget only as a deliberate config edit. `indusk context check-pointers` verifies pointers resolve and refuses hand-copied `**Version**:` claims. — see `/guide/context-budget`
- **Decay layer**: `indusk agent sweep` archives current.md sections older than `agents.sweep_ttl_minutes` (7d default; ≫ the 60-min display TTL) to `.indusk/archive/current-md-archive.md`; `indusk plans archive-dead` moves all-draft stale plans (`planning.dead_draft_days`, 30d) to `planning/archive/`. Archive, never delete; malformed input blocks/keeps; master.md non-draft rows protect plans. — see `/reference/cli/plans`
- **Hub push/pull**: `indusk sync promote <lesson>` → machine-global hub (`$INDUSK_HOME/hub/lessons/`, provenance-stamped, manifest-versioned); `indusk sync pull` (run by catchup) merges hub + bundled community channel — additive-only, idempotent, local wins. — see `/reference/cli/sync`
- **`/catchup` is dieted**: no CLAUDE.md re-read (auto-injected), targeted current.md reads (shared region + live sections keyed off `agent list`), `list_plans { active: true }`, sweep dry-run + hub pull. `/handoff` runs the real sweep. Measured 55k → ~8.2k tokens. — see `/reference/skills/catchup`
- **`.indusk/current.md` is per-agent sections** (`## Project (shared)` anchor + `## Session <short> — <task>` blocks, matched by full UUID from `**Session ID**:`); CLAUDE.md is the architectural layer, current.md the operational layer. Write your section only via `mcp__indusk__update_current_section` (typically at `/handoff`); commit like any file. `merge=union` in `.gitattributes` merges concurrent appends; all mutations go through the `current.md.lock` file lock (the load-bearing primitive between concurrent processes on one machine — git mediates nothing between them; `merge=union` covers concurrent appends across machines). — see `/decisions/multi-agent-coordination`
- **Session IDs sanitize at the boundary** — every `$CLAUDE_CODE_SESSION_ID` / `--session-id` flows through `sanitizeSessionId()` (`apps/indusk-mcp/src/lib/agents/session.ts`) before any path join; section bodies flow through `sanitizeSectionBody()` (rejects the four structural marker patterns). Never bypass these chokepoints. `CLAUDE_CODE_SESSION_ENV_VAR` is the single source for the env-var name.
- **`indusk agent list` shows worktree/branch recomputed live and is an implicit self-heartbeat**; it flags `⚠ collision` when ≥2 live sessions share a tree. The heartbeat preserves last-known worktree/branch on non-git cwds (a workbench root before its first `workbench sync`/`restore` has no git history yet). — see `/decisions/worktree-visibility`
- **Workbench topology is DECLARED, never inferred** — `worktree.repos[]` with optional `path` / `worktrees` per repo; the legacy `wrapped_repo` reduces to a one-element list and **absence means flat**, so nothing migrates. One reader (`readWorkbenchRepos` + `repoDir`/`worktreesDir`), never the raw field; `hooks/_hook-paths.js` and `workbench-helpers.sh` carry deliberate ports — change all three together. **`isWorkbench` is true for any config that declares repos, with or without `shape`** (a shapeless `repos[]` read as flat while every other reader treated it as a workbench). In bash, `setup-worktree`, `refresh-worktree` and `preflight` all resolve the trunk through `_wt_resolve_trunk_dir` and slugs through `_wt_resolve_target` (root + every declared `worktrees` dir) — no script keeps a private scan or reserved list. Names and paths are segment-guarded via `lib/path-segment.ts`. — see `/reference/cli/workbench`
- **`indusk workbench` = restore / sync / status / migrate-layout.** Restore materializes a cloned workbench; sync is commit → pull → push (`merge=union` on append files), triggered by a debounced `PostToolUse` hook guarded on `worktree.shape` so it is **inert in normal-mode repos like dusk**. **The wrapped repo is never auto-committed.** Partial failure is always loud and non-zero. Restore materializes each repo at `repoDir(repo)` (declared `path`, else name — where health, status, doppler and the update nudge look) and is idempotent there; it once cloned at the name, making a second copy beside a repo declared at a `path`. — see `/guide/workbench-sharing`
- **Ignore rules are generated from declared locations** (one precise line each); a FLAT workbench whose own `.gitignore` lacks the deny-by-default rule is **refused**, never rewritten (`--no-ignore-check` overrides). Generator and checker share named constants — they drifted twice when each restated the string. — see `/decisions/versioned-workbench`
- **Tooling detection runs over the declared repos, never the wrapper** — `detectTooling` (`lib/detect-tooling.ts`) iterates `resolveCheckRoots`, the same roots the health checks use, because a workbench root holds no code and a detection against it records nothing; a split verify without a runner reports every row **unverified under a clean verdict**, the exit code lying by omission. `update` writes `verify.testRunner` for a workbench that predates this; an explicit `verify.testCommand` is never touched. — see `/reference/cli/verify`
- **`indusk verify` judges the code repo in a one-repo workbench**: `resolveExecutionRoots` gives it a plan root and a code root; red tests run in the code repo (with the command configured at the plan root — `Test` paths are code-repo-relative when split), phantom asks "what changed" of the code repo and "what got checked" of the plan repo, goalposts stay on the plan repo. A clean verdict records both HEADs (`sha` + `codeSha`); **a record without `codeSha` is never a code baseline** — verify bootstraps the code repo from its root commit and reports `merge-base`. Zero or several declared repos still refuse by name. — see `/reference/cli/verify`
- **The lifecycle is one definition** — `lib/lifecycle.ts` owns positions (nouns: research … archived, `monitor` reserved), activities (verbs, inside `executing` only), `GATE_STAGES` and `RITUAL_ORDER`; `parsePlan`, `checkRetrospectiveReadiness` and the admin read it; pinned by `lifecycle-single-definition.test.ts`. `test-plan` is a document position (the old private order skipped it). — see `/guide/plan-lifecycle`
- **A plan that adds a lifecycle position, activity or gate kind also adds its admin rendering, in the same plan** (a Document gate item) — the label maps in `components/bars/labels.ts` are `satisfies Record<…>` over the lifecycle's unions and `lifecycle-render-parity.test.ts` names the member until a renderer exists. The active phase is the most recent boundary record among open phases; first-open-phase with a visible hint when there are none; a malformed record file is an error block, never a guess. — see `/reference/admin-ui/overview`
- **Worktree-per-plan is the default**: every impl's Phase 1 opens with a worktree kickoff; opt out via `worktree: none` (also `no`/`off`/`false`/`skip`) in impl frontmatter. `resolveWorktreeDecision` + `detectTreeContext` in `apps/indusk-mcp/src/lib/worktree/decision.ts`.
- Plans live in `.indusk/planning/{kebab-case}/` following research → brief → test-plan → adr → impl → retrospective. Use `/planner` before implementing; don't jump to code. Cross-reference related plans by path; update both when work overlaps.
- **Papers are plan documents**: `kind: paper` is declared in frontmatter, never inferred from filenames. A folder of papers with no lifecycle document is a `paper`-stage plan (the stage is never in `STAGE_ORDER`; a lifecycle document always wins). Status vocabulary `draft | accepted | published`; anything else reads `malformed`, never a silent draft. Staleness is derived on every read from `paperContentHash` (SHA-256 of the document minus `status` and the `published` block) and never stored — `published (stale)` reports, it does not block. — see `.indusk/planning/archive/writing-skill/adr.md` + `/reference/cli/plans`
- **`papers.destinations[]` is ensured on `update`** (empty list, keyed on block presence like `cleanup`) and resolved by exactly one function, `resolveDestination` (`lib/papers/destination.ts`): a `path` expands `~` and resolves against the project root; a `repo` is a `worktree.repos[]` declaration and is **refused outside a workbench** ("only paths are accepted here"), because a project that is not one has no declarations to read. Resolution is pure; existence and git-ness are the publish step's checks. — see `/reference/cli/papers`
- **A skill's `description` is its routing key.** It is the only thing the model sees before deciding to invoke a skill without the slash, so it names the triggers in plain words (`write`: draft, outline, revise, review, publish a paper, thesis, or essay). Any change to a description re-runs the manual plain-language invocation check in the plan's dogfood procedure; a routing miss in use is fixed in the description text, not with a hook. — see `/reference/skills/write`
- **`indusk papers publish` commits in the destination and never pushes by default** (`--push` is explicit; deploy runs on push). Preconditions refuse with nothing written: source uncommitted, target page dirty, destination missing or not git, index without its marker pair. A **committed** hand edit is overwritten and named in the commit body (the destination is a build artifact). Every publish also makes one provenance commit in the source; the write-back is a **text edit** of the frontmatter (`lib/papers/provenance.ts`), never a gray-matter round trip, which rewrites `date: 2026-09-09` into an ISO timestamp. — see `/reference/cli/papers`
- **Plan hierarchy is declared top-down, in frontmatter**: the root `master.md` names `parents:` + the `roadmap:` order; each parent's own `master.md` names its ordered `subplans:`. Children declare nothing — one source of truth per link, so the two sides can't drift. **The plan inventory always comes from disk** (`parseAllPlans`), never from a list; declarations add structure and can never subtract a plan. A missing/corrupt/absent key degrades to the flat list. Declaration names are boundary values — segment-guarded (no `/`, `\`, `..`) and first-occurrence-deduped inside `readPlanDeclarations` before any path join or render. Archived children resolve as real items (active wins name collisions), never placeholders. `readPlanDeclarations` in `apps/indusk-mcp/src/lib/plan-parser.ts`. — see `/reference/cli/plans`
- **Every impl phase has gates** (implementation, verification, context, document; OTel only when `otel.role` is unset/`service` — dusk is `library`, so no OTel sections here). Hooks enforce: `validate-impl-structure.js` at write time, `check-gates.js` at phase transitions, `gate-reminder.js` nudges. Gate policy via `gate_policy` frontmatter (`strict`/`ask`/`auto`, default `ask` — skips need conversation proof).
- **Trajectory rows may carry an optional `Test` column** naming test **files** (comma-separated); `atdawn verify` runs them through the project's own command and reads the **exit code** — never by parsing runner output, which would hardcode tool knowledge into core (extensions own that). Absent ⇒ the row is reported **unverified**, never counted as passed. `verify.testCommand` in `.indusk/config.json` is the explicit escape hatch; an unknown runner without one is a refusal, not a guess. — see `/reference/cli/verify`
- **Test Trajectory** is mandatory in new impls (`trajectory: required`): table `ID | Asserts | Writable at | Passes at | State`, IDs `T`- or `A`-prefixed (`/\b[TA]\d+\b/` — deliberately not `[A-Z]`), phase Verification references IDs, Deferred Verification rows need `reason:`/`would require:`/`mitigation:`, `### Trajectory Rationale` required for Phase 1+ writable rows (`rationale_baseline: N` exempts refactor baselines). Writable-at = earliest authorable phase, not the fix phase. — see `/decisions/tests-first-planning` + `/guide/test-trajectory`
- **Close-out rituals**: `/work` → `/falsify` (authors a Falsification Phase — never runs tests inline) → `/work` → `/cleanup` (decomposition ritual; `cleanup` config block threshold is attention-focus, NOT a blocking cap) → `/work` → `/retrospective`. Retrospective Step 0 hard-blocks unless both rituals are terminal or explicitly skipped (`falsification: skipped` + reason / `cleanup: skipped` + reason). Ritual-phase detection matches titles that START with the ritual word. — see `/decisions/falsification-ritual` + `/decisions/cleanup-ritual`
- **Shape's craft rules come from enabled extensions and hardcode none** (`lib/shape/rules.ts`) — every extension that `provides.skill` contributes its prose unparsed, with no domain-vs-tool filter (the manifest has no such taxonomy, and inventing one in core is the hardcoded judgment A11 forbids). The rule set carries its own intra-unit/inter-file scope declaration, so the line travels with the rules. — see `/guide/shape`
- **Retrospective compaction step**: plan close demotes the plan's Current State narrative to one line + archive link, compresses any Conventions entries it authored to rule + pointer, and collapses one old entry per close (the periodic pass). — see `/guide/context-budget`
- **Thin-lane eval rail**: `atdawn run` queues each loop commit to a pending-eval JSONL under `.indusk/eval/` (created on demand — absent means the queue is empty, not broken; it may run where no `claude` CLI exists); `eval-trigger.js --drain-pending` evaluates each exactly once — the ledger is written *before* spawn (crash = gap, never double-eval) but is **provisional**: a failed evaluator un-drains its record, so a machine that cannot evaluate never destroys the backlog. `/rail-check` owns the drain; `check_health` surfaces it; eval state stays out of work-product staging; commit messages account for every item a commit contains. **Queued records carry `repo`** (the repository the commit landed in, realpath-normalized) when the loop knows it — across a workbench split, always — and the drain hands it to the hook as `--git-root`, which in CLI mode outranks the walk-up's newer-HEAD attribution; a record without `repo` resolves as before. — see `/decisions/dawn-hook-parity` + `/guide/rail-check`
- **Eval agent** ("evaluator", never "judge"): PostToolUse hook on `git commit` only — regex `/\bgit commit(?=$|\s|;|&|\|)/` (anchored + right-edge lookahead; never String.includes for shell triggers). Skips when `tool_response.exit_code` ≠ 0. Persistent session via `claude --resume`; `--mcp-config .mcp.json` + `--permission-mode bypassPermissions` are load-bearing for MCP access. `eval.model` config (default sonnet) affects fresh calls only. Findings persist via `indusk eval findings/fix/ignore`. Disable per-project with `eval.enabled: false`. — see `.indusk/planning/archive/eval-agent-mcp-access/`
- Verification items in impls are runnable commands with expected output, never "verify it works". Before touching shared code, grep for importers/callers to understand blast radius.
- **`pnpm publish` packs the WORKING TREE, not a commit** — verified against the published 1.44.1 tarball, whose files matched main exactly including changes made after the bump. So the question is never "was the bump recent enough"; it is **does this tree contain the finished work**. Worktree-per-plan makes that structural: every plan lives on a `plan/*` branch in its own worktree, so a publish from a perfectly clean main is blind to it by construction. **The rule: bump on main, after the branch is merged** — never on a branch, never while a plan's close-out is outstanding. `pnpm release` enforces it (`scripts/release-guard.sh`, `SKIP_RELEASE_GUARD=1` overrides): it refuses a dirty tree, a HEAD that is not the `chore(release): <version>` commit, and any unmerged `plan/*` branch touching packaged paths (planning-only branches are reported, not refused). **Before saying anything about whether a publish is current**, read `git rev-list <release-commit>..HEAD` and `git for-each-ref refs/heads/plan/* --no-merged HEAD` — never infer staleness from a version number (a session once called a minutes-old publish stale, inverting cause and effect).
- Commit cadence: one commit per checklist item on a `plan/{name}` branch; `git add -p`, intent-named messages; merge + delete fast. MonoRepo commits stay siloed per context.
- Extensions own tool knowledge (health checks, setup, verification) — don't hardcode tool facts in indusk-mcp core. Required-by-default extensions flow through `autoEnableExtensions` Pass 1; opt out via `disabled_extensions` in config. Extensions ship `.env.example` as the env-var source of truth — NEVER a real `.env`.
- **`indusk setup <cloned-repo>` one-shots workbench creation** (symlink-in-place trunk + delegate to `init --workbench`); config-aware collision guard; atomic cleanup on failure. Workbenches are per-developer scaffolding — only the wrapped repo is shared. — see `.indusk/planning/archive/workbench-setup-command/`
- In local mode (`--local`): `.git/info/exclude` handles ignores (per-clone); `indusk pr-clean`/`pr-restore` strip/restore InDusk settings around PRs.

## Key Decisions

- Context skill is pure markdown instructions; CLAUDE.md keeps a fixed 6-section structure — see `.indusk/planning/archive/context-skill/adr.md`
- Biome over ESLint; global config is the floor, project extends — see `.indusk/planning/archive/code-quality-system/adr.md`
- Vitest as committed test runner with adaptive first-connect setup — see `.indusk/planning/archive/verify-skill/adr.md`
- Document skill (per-phase gate) + retrospective skill (closing audit + docs handoff) — see `.indusk/planning/archive/document-skill/adr.md`
- GSD-inspired: lessons registry, boundary maps, blocker protocol, forward intelligence — see `/decisions/gsd-inspired-improvements`
- Plan-gate enforcement via Claude Code PreToolUse hooks — see `.indusk/planning/archive/enforce-plan-gates/adr.md`
- Extension system: one system, two sources (built-in + third-party), replaced domain skills — see `.indusk/planning/archive/extension-system/adr.md`
- Excalidraw for informal diagrams, Mermaid for formal; ExcalidrawEmbed in VitePress — see `/decisions/excalidraw-extension` + `/decisions/vitepress-excalidraw-embed`
- OTel as core instrumentation, role-aware gate via `otel.role` — see `/decisions/otel-extension`
- Local init mode (`.indusk/` home, `config.json` profile, `--local`) — see `/decisions/local-init-mode`
- Test Trajectory as canonical impl shape; four validator rules; structural phase-close gating — see `/decisions/tests-first-planning`
- Falsification ritual between work and retrospective (goal-flipped bounty hunt; phase-authoring as of 1.27.4) — see `/decisions/falsification-ritual`
- Cleanup ritual as falsify's twin (no fifth gate, no LOC ratchet — threshold is attention-focus) — see `/decisions/cleanup-ritual`
- Three-tier agent roles + highlights queue — see `.indusk/planning/archive/agent-roles/adr.md`
- Admin UI: standalone Next.js read-only viewer — see `/decisions/indusk-admin-ui`; hosted as machine-global daemon + registry — see `/decisions/admin-ui-hosting`
- Local telemetry: native-binary Jaeger + otelcol daemon, `indusk telemetry *` CLI, jaeger_mcp wired into project `.mcp.json` — see `.indusk/planning/archive/local-telemetry/adr.md`
- `rationale_baseline` frontmatter for refactor-baseline plans — see `/lessons/rationale-baseline-frontmatter`
- Doppler extension as the default env layer (replacing composable.env); worktree env auto-provisioning from one service token — see `.indusk/planning/archive/doppler-extension/adr.md`
- Multi-agent coordination: per-agent sections in one current.md + `update_current_section` MCP write surface + worktrees per agent — see `/decisions/multi-agent-coordination`

## Known Gotchas

- Tailwind 4 requires Node 22 ("Cannot find native binding" on 18). OTel auto-instrumentation must load before other imports (`node --import` / Next instrumentation hook).
- Skill files are `SKILL.md` (caps). Skills and hooks are package-owned: edit `apps/indusk-mcp/skills/` + `apps/indusk-mcp/hooks/`, resync installed copies (`skill-sync-parity` test pins byte-equality; dusk has no global `indusk update`).
- Biome 2.x API differs from docs: no `noVar`, overrides use `includes`. Match schema to installed version.
- `validate-impl-structure.js` re-validates the whole file when an edit's `new_string` contains a phase header (the regex matches `#### Phase` too) — scope edits to checklist items to limit re-validation. Trajectory hook JS ports (`check-gates`/`gate-reminder`/`validate-impl-structure`) are minimal mirrors of `apps/indusk-mcp/src/lib/trajectory/` — change TS + every JS port together.
- **Phase identity is `{kind, number}`** — `PhaseCompletion.ref`, the Shape functions and `findPhaseStart` take a `PhaseAddress` (a bare number = the build phase, never a test phase); a boundary record without `kind` is build by rule. `Writable ≤ Passes` enforced at write time. Falsification log fields are single-line (library rejects line separators). Frontmatter regexes for value-bearing keys must be line-anchored (the `rationale_baseline` lesson).
- **Never predict Edit results with `String.replace`** — its replacement-string `$`-substitution (`$$`/`$&`/`` $` ``/`$'`) diverges from the Edit tool's literal semantics; use an index-splice (the claude-md-budget A16 lesson). Guard empty `old_string` before predicting.
- **Hooks discovery is globSync on BOTH sides** (init + update) — a hardcoded hook list silently ships settings registration without the file (the eval-trigger lesson). New hooks also need a targeted settings-ensure block in update.ts for pre-existing projects (eval-trigger + claude-md-budget precedents). **Hook-local `_`-prefixed modules** (`_hook-paths.js`, `_pending-drain.js`) are imported by hooks, not registered as hooks: they need NO settings entry, but they must exist in `.claude/hooks/` or the importing hook dies at load — `globSync("*.js")` copies them, so keep them in `apps/indusk-mcp/hooks/` and never resolve a hook's import outside that directory.
- commander@13 silently drops duplicate parent+subcommand options — declare flags on the parent only, read via `optsWithGlobals()`.
- gray-matter on malformed YAML throws in plain Node but returns `data: {}` inside vitest — detect malformed structurally, don't rely on throwing.
- **The admin sidebar tree is derived entirely from declarations** — one root node (the root master, `readPlanDeclarations().root`) with parents and unclaimed plans beneath it; directly under the root means unclaimed, not a reader bug; grouping lives in `PlanList.buildGroups`; subplan children resolve against active+archived with active winning, identically in sidebar and detail; parents render additively via `ParentPlanView`, doc-less plans header-only. **Phases render through `parseImplString` (the `impl-parser` subpath, filesystem-free core) — never a local heading regex; rows attach by `(passesAtKind, passesAt)`.** Badge maps: `ui/badge-variant.ts`; research reads: `lib/research-reader.ts`. Browser tests mock every export a component imports, from the module it imports from. HTTP-level tests boot `next dev` through `__tests__/helpers/next-dev.ts`, one at a time — Next locks `.next/`, so `fileParallelism: false` is load-bearing and a stray dev server on the app dir fails every smoke; the live rows drive it with Playwright from the node project. — see `/reference/admin-ui/overview` + `/reference/admin-ui/component-conventions`
- **The papers module map, one home per fact**: `lib/papers/summary.ts` owns paper parsing (vocabulary, summary, content hash, staleness, next step) and `plan-parser.ts` re-exports its public names so the `planning/plan-parser` subpath and the admin's import hold; `papers/provenance.ts` owns the `published` block's read and write shapes (`PublishedRecord` / `Provenance`, pinned to the same keys by count in `papers/shared-definitions.test.ts`); `lib/git.ts` owns `snapshotPaths` / `restorePaths`; `papers/publish.ts` is the ten-step procedure only. A second `data.published as {…}` narrowing anywhere under `src/lib` fails the pin. — see `/reference/cli/papers`

The status-keyed detectors today: `archive-dead.ts` (blocking set) and `plan-tools.ts` (`isActivePlanStatus`). **`indusk papers publish` pushes last and never lets a git failure escape past a commit it made**: every touched destination path is snapshotted before writing and restored on failure through the destination commit; a failed source commit refuses naming the destination commit that now exists; a failed push is a warning with exit 0. Divergence is judged on the page being replaced (the old path, for a retitle) before `git mv`.
- **The admin Papers section renders from the shared parser's `papers` field** (`parsePlan` via the `planning/plan-parser` subpath; the reader adds only each body). The `published (stale)` badge is derived from the content hash on every read, so a paper edited after publish shows stale with no write anywhere; `paperStatusToBadge` / `paperStatusLabel` live in `ui/badge-variant.ts`. A papers-only plan takes the parser's paper-stage status as its header status and renders no Falsification section. — see `/reference/admin-ui/overview`
- `next/link` needs a `vi.mock` stub in vitest browser tests (synchronous factory). Hand-written `TrajectoryRow` fixtures carry `writableAtKind`/`passesAtKind` — the admin's `tsc` was red for a month unnoticed until `typecheck.test.ts` made it a test. Admin UI: `dynamic = "force-dynamic"` in root layout is load-bearing; markdown renders only through the `<Markdown>` wrapper (swap libraries in `Markdown.tsx` alone); registry (`~/.indusk/projects.json`) is never auto-pruned — `indusk ui prune [--dry-run]` removes dead entries with a `.bak.<ISO>` first, and the CLI test helper's `runCli` pins `INDUSK_HOME` to a temp dir by default (`registry-leak-scan.test.ts` is the second line — a per-file `??=` yielded to an exported `INDUSK_HOME`); malformed files quarantine to `.corrupt.{ISO}.bak`, never silently overwrite; daemon identity = PID liveness AND port-listening (PID reuse false-positives otherwise); scorecard-to-plan join is date-range approximate.

Telemetry binaries ship as platform-split optionalDependencies; bump via `packages/telemetry-binaries-shared/UPSTREAM.json` + `scripts/build-telemetry-binaries.sh`. Telemetry registry stores realpath-normalized paths (macOS `/var` ↔ `/private/var`).
- `extensionsDisable` fires `on_disable` BEFORE renaming the manifest dir (order is load-bearing); `INDUSK_BIN` env overrides the bare `indusk` prefix in extension-hook commands (test-critical).
- **Eval rail invariants** (hard-won — see `.indusk/planning/archive/eval-agent-mcp-access/`): the resume prompt must include Step 4 (highlights) — shrinking it silently starved the queue for 197 evals; `markProcessed` rejects duplicates at write time (`already_processed: true` → STOP, don't re-materialize); `--mcp-config` + `bypassPermissions` literals are pinned by regression test; never use backwards-anchoring phrasing ("as before") in the resume prompt. Post-makeover: materialization writes lessons via `add_lesson`; a reappearing `graph_capture` reference is a test failure. **Old persistent eval sessions pinned to deprecated models 404 on resume — recovery: delete the session state so a fresh spawn picks the current model**. **In a workbench a commit is attributed to the repository that received it** (the workbench repo receives commits too): one declared repo + git root at the workbench → `resolveStateAndGitPaths` picks the newer HEAD (tie/missing → code repo) and returns `attribution`; several declared → `refusal`, logged and, in hook mode only, emitted as `additionalContext`. — see `/guide/rail-check`
- `indusk agent register/list/prune/sweep` and the MCP write tool all take the current.md file lock; `agent list` heartbeat never wipes worktree/branch on non-git cwds. Malformed `Last updated` timestamps are KEPT everywhere (prune, sweep) — never destroy data on bad input.
- The eval hook only fires inside Claude Code sessions (PostToolUse), needs `claude` in PATH; check `.indusk/eval/results.log` + `system.log` when scorecards go missing.
- **The cleanup lib throws on non-git roots and refuses workbench roots by declaration** (`isWorkbench`, naming the declared repo dirs): a versioned workbench root is a git repo whose diff holds plan documents and no code, so a silent `[]` there reads as "checked and clean" for code never seen — the same gap `verify` closed with `resolveVerifyRoots`. Its changed-files diff resolves merge bases through candidate fallbacks (`origin/main` → `main` → `master` → root); `isNew` uses `git cat-file -e` exit codes, not the output-swallowing `git()` helper; `.indusk/` is excluded from flagging; ritual-phase terminality needs ≥1 checklist item and sees nested unchecked items.
- `indusk setup` guard is config-aware (real workbench → "run update"; foreign dir → "remove it"); failed setup rmSyncs only what it created (symlink-safe). Worktree extension: a consumer's config schema is shipped beside its worktree-configs by `on_enable` and refreshed on every enable (the starter config's `$schema` is `./config.schema.json`); `apply_commits[]` is upstream-file-overlay via skip-worktree, NOT cherry-pick; preflight env contract is `CHANGED_FILES` + declarative `preflight_env{}` globs (`set -u` — read undeclared keys with `${VAR:-}`); per-worktree state lives under the gitdir (`indusk-overlay-state.json`), not the working tree.
- `.indusk/graph/semantic-graph.log` still exists on disk in old projects but nothing reads or writes it post-makeover; safe to delete manually.
- **`resolveImplPath` (`lib/impl-parser.ts`) and `TERMINAL_STATES` (`lib/trajectory/parser.ts`) are single-definition on purpose** — two enforcement lanes must agree, so a copy is a silent divergence, not a duplicated line. Pinned by `shared-resolution.test.ts` asserting **one definition exists**; no behavioral test can catch a divergence that has not happened yet. `hooks/check-gates.js` mirrors the state set inline — deliberate port; change TS and every port together. **Joined by the async `git()` runner (`lib/git.ts`) and the phase-block scan (`lib/shape/impl-blocks.ts`)**, pinned by `shape/shared-definitions.test.ts`. A git *primitive* belongs in `lib/git.ts`, not in a domain folder — a primitive kept inside `verify/` or `shape/` gets **copied** by the next domain instead of imported. `cleanup/oversized.ts`'s `git()` is excluded: synchronous, swallows errors — a different function sharing a name. **Fourth: `lib/worktree/layout.ts`** (`RESERVED_ROOT_DIRS`, `listWorkbenchSubdirs`, `worktreeOwner`, `linkTrunk`), pinned by `workbench-repos-single-definition.test.ts` — a primitive inside a **command** module gets copied by the next command too. **Fifth: `resolveExecutionRoots` (`lib/worktree/roots.ts`)** — "where is the plan, where is the code" for run, verify and the cleanup scan; one declared repo resolves to a split, zero or several refuse by name, each consumer decides what a split means; pinned by `execution-roots-single-definition.test.ts`. **Sixth: `headSha` / `headShaOrNull` (`lib/git.ts`)** — `verify/git.ts`, the commit cadence and the run loop had each spelled `rev-parse HEAD`; pinned by `head-sha-single-definition.test.ts`. — see `/lessons/dawn-verify`
- **Impl phases are two sequences ordered by document position** — `### Test Phase N` + `### Build Phase N`; `### Phase N` still means build phase N, so no existing impl changed. `phaseOrdinal` **reduces to the phase number when a document has no test phase** — that reduction IS the backward-compatibility guarantee, not a claim about one. `Phase 0` is present by definition; a phase not in the document is a forward reference and is skipped. **Test Phase 1 is the register** (`#### Deferred to Test Phase N` / `#### Deferred to Build Phase N` / `#### Regression Guards`), it **absorbs** `### Trajectory Rationale` (one home per fact), it must carry its Verification gate, and new impls opt in via `test_phases: required`. Gate A compares `<=` not `===`, so a row left unwritten blocks every later close. — see `/decisions/test-phase-structure` + `/guide/test-trajectory`
- **Heading/parsing definitions are single-definition on purpose, pinned by counts** — `src/lib/impl-headings.ts` (phase + gate patterns) and one trajectory-row parser under `hooks/`; each `_`-prefixed hook module mirrors exactly ONE `src/lib` module, so "change the TS and every port together" is checkable by reading two filenames. Duplicates here diverge **silently**: one copy couldn't read `Test Phase N` (Gate A matched nothing), another omitted `state` (every row read non-terminal). Two silences, one parser. **`_impl-phases.js` is the one hook-side phase/checkbox-item walk** (`parseImplPhases`, mirroring `impl-parser.ts`'s `getPhaseCompletion` family), imported by `check-gates.js` and `gate-reminder.js`, pinned by count (A24) — the two carried copies until workbench-trust-fixes' cleanup, gate-reminder's recognizing one gate kind fewer. Test fixtures likewise share one throwing git runner, `src/__tests__/helpers/test-git.ts` (`git`, `headOf`, `initRepoWithCommit`); helpers that return `{ code, stdout }` are a different contract. `gateHeading(kind)` puts the phase number at capture 1. A validator parsing **zero** phases refuses — `## Phase N` (h2) is invisible and two impls were passing vacuously that way. — see `/reference/trajectory/parser`
- **`fencedLineMask` is load-bearing structure** — a deferral carries the deferred test's body, so impls hold arbitrary text. A fence closes only on the **same character at ≥ the same length with nothing after it** (CommonMark); nest by lengthening. An unterminated fence **masks nothing** (fails open, so one missing backtick cannot silently delete every phase below it from all three parsers) and the validator refuses, naming the line. — see `/guide/test-trajectory`
- **Verify never reports "could not check" as a verdict** — asserting a failure you never observed is as dishonest as asserting a pass you never observed. `Test` paths are **repo-root-relative** (the command runs with `cwd` = repo root; a package-relative path in a monorepo resolves to nothing); unresolvable or `manual:`-prefixed rows report **unverified**, never red; `readLedger` **throws** on a malformed line rather than skipping it (a shortened chain degrades into bootstrap mode = a confident report against the wrong baseline). The derived vitest command must **not** pass `--silent` (boolean in v4 — it swallows the appended file path). — see `/decisions/dawn-verify`
- **The phase-boundary record (`.indusk/phase-boundary.jsonl`) is generic and is machine state** — it says where a phase opened, and Shape/`verify`/`Challenge` all read the same artifact rather than each growing a near-identical ledger. Two rules: every changed-file scope must exclude `.indusk/` (the record is written when a phase *opens*, so counting it makes every phase look productive before doing anything — the verify-ledger trap arriving early), and `readBoundaries` **throws** on a malformed line rather than skipping it (a lost start widens the review scope to earlier phases' code, which looks exactly like Shape working). **The writer validates with the reader's predicate** (`boundaryRecordProblem`) — one bad append blinds every reader of the whole file, so `recordPhaseStart` refuses it naming the field.
- **Every way a phase-boundary scope can be wrong is silent, so every fallback leans toward over-reporting** — a re-read is recoverable, lost work reported as success is not. `findPhaseStart` takes the earliest record, deletions drop out, untracked files are dated by mtime, and `verificationIsGreen` counts nested unchecked items (deliberately stricter than `getPhaseCompletion` — different question, not a second copy). — see `/guide/shape`
- **A library the skills call is not shipped until it is in `package.json` `exports` AND its documented invocation has been run verbatim.** Nothing here executes a command written in a skill, and tests that import the source cannot see the path a real user takes. — see `/lessons/tested-is-not-reachable-run-the-documented-command`
- **A newly tracked InDusk artifact must be registered with every "what changed" detector AND given a merge strategy, in the commit that first writes it.** The detectors are `phantom.ts`'s `isMachineState`, `shape/changed.ts`'s `isNotCode`, `cleanup/oversized.ts`, and `.gitattributes`; those predicates are deliberately **not** shared. — see `/decisions/lifecycle-rebalance`
- **Any detection keyed on "what else changed" must exclude InDusk machine state** (`.indusk/verify/`, `.indusk/eval/`, `.indusk/phase-boundary.jsonl`) — the verify ledger is tracked, so once committed it appeared in every later diff and silently disabled phantom detection; `changedPathsSince` must also include untracked files or unstaged work looks like no work. Phantom is deliberately narrow (fires only when the diff touches nothing but `impl.md`, implementation items only) — broadening it produces false positives that get the detector disabled. Ledger failure-safety is the **inverse** of pending-eval's: append only *after* a clean verdict. — see `/lessons/dawn-verify`
- **`indusk run`'s gate covers tool surfaces, not intentions** — any tool that can mutate files must be routed through the `{tool_name, tool_input, cwd}` envelope or it is a hole in Tier-1 by construction (falsification found `bash` rewriting checkboxes the `edit` gate would refuse; it is now snapshot-gated + reverted, and escape-scanned best-effort — NOT sandboxed). The invoker fails **loud**: exit 2, any other non-zero, and a timeout kill all block, because an unattended loop must never read silence as permission. — see `/reference/cli/run`
- **A safety argument written in a comment is not enforced by the code around it** — grep the codebase for comments asserting an invariant and check the control flow actually delivers it. Workbench sync's blind merge was justified by "step 1 committed it" while step 1 could fail and fall through; `status` reported a never-pushed branch as "in sync" because `rev-list A..B` *errors* on a missing ref and the error path read as `ahead = 0`; `restore` printed "trunk linked" where `linkTrunk` had correctly refused. Each reported the worst case as the most reassuring one. — see `/reference/cli/workbench`
- **Tests that need a versioned workbench use `src/__tests__/helpers/versioned-workbench.ts`** (root `git init`ed, `worktree.repos[]` with `path` / `worktrees`, four one-repo layouts — flat legacy `wrapped_repo`, nested, sibling, declared `path` — exported as `LAYOUTS` for `describe.each`; repo dirs from the production `repoDir`). A test about where the code lives runs over all four or it is blind to three. A fixture that never `git init`s its root reproduces the pre-1.37 shape and cannot see any of the workbench-trust-fixes class — the regression net was structurally blind to all of them until this helper existed. — see `.indusk/planning/archive/workbench-trust-fixes/`
- **PostToolUse hooks: stderr at exit 0 goes to the debug log only.** A message meant for the model is a stdout JSON envelope carrying `hookSpecificOutput.additionalContext`, emitted via `console.info` (on the `noConsole` allowlist; `console.log` gets swept). `gate-reminder.js` did neither for its whole life and was never heard — and its private trajectory parser read `Build Phase N` cells as `NaN`, so it also could not have nudged a modern impl. It now runs on `_impl-headings.js` + `_trajectory-parser.js` like the other hooks. — see `.indusk/planning/archive/workbench-trust-fixes/`
- **Hook commands are registered by the project root, never relative to the cwd** — `hookCommand(name)` (`lib/hook-command.ts`) is the one definition, `node "${CLAUDE_PROJECT_DIR:-.}"/.claude/hooks/<name>.js`; `absolutizeHookCommands` rewrites the exact old form on `update` and on `init` before its merge. Claude Code runs hooks in the session's cwd and treats a load failure as non-blocking, so the relative form was a gate that switched off silently after any `cd` (observed 2026-09-10). Not fixable by registration: a session launched from a subdirectory, or one already running when settings change (hooks snapshot at start). — see `/guide/#3-hooks-enforce-what-discipline-won-t`
- **Enabling an extension ships only its `manifest.json`** (plus `.env.example`), and an enabled extension's `on_enable` **never fires again** (`autoEnableExtensions` skips what is enabled; `extensionsUpdate` is third-party only). So a file an extension's output points at must be shipped by its hook, and reaches existing projects only via a declared `on_update` — fired through `extensions.ts`'s one runner, which applies the test-critical `INDUSK_BIN` substitution. Package-owned files under `.indusk/` are machine-local: ignore them by name (`MACHINE_LOCAL_RULES`, every layout) or `workbench sync` shares them. `topUpManagedIgnore(root, { layoutDeclared })` tops up **per rule**, in two blocks — deny-by-default is flat-only, and **a guard that returns early for one layout must not carry unrelated work behind it**. — see `/lessons/worktree-config-schema-pointer`
