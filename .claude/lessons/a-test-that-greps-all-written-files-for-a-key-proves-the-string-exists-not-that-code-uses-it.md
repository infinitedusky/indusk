# A test that joins every file a command wrote and looks for a key proves the string exists somewhere, not that the code uses it — assert per file on what it hands its SDK

The init-scaffold-runtimes rows T3 and T7 of a-new-project-starts-instrumented joined all written files and checked that the service name and the `indusk.project` and `deployment.environment` keys appeared. The settings file always contains those strings, so the rows pass even if an instrumentation file stops passing `settings.serviceName` or `settings.resource` to its SDK (the cold audit's finding). Rule: for a clause about what code does, assert on each setup file separately and on what it hands to its SDK (the constructor argument, the resource line), or run the code; never a whole-output grep for a string a sibling file always contains.
