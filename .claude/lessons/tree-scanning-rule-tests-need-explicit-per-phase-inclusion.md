# Any whole-tree scanning rule test (not just single-definition pins — also structural rules like everyday-tests-never-wait) is invisible to per-phase `vitest related`; three plans in a row hit this independently

Extends `whole-tree-scan-pins-are-invisible-to-vitest-related` (written after two plans hit the single-definition-pin version of this gap). A third plan hit the same root cause through a different rule test, confirming the gap is general to any whole-tree-scanning rule, not specific to single-definition pins.

`vitest related <changed files>` selects tests by import graph. A rule test that instead scans the whole tree — for a duplicated string/shell-command literal (a single-definition pin) OR for a structural property like "no everyday test waits on a real clock or server" (`everyday-tests-never-wait`) — has no import edge to the files it's checking. It's a scan, not a dependency, so `vitest related` never selects it for a phase that introduces exactly the violation it exists to catch.

**Why:** evaluator-waits-out-limits (dusk, 2026-10-10, archived at `.indusk/planning/archive/evaluator-waits-out-limits/`). `evaluator-limits.test.ts` read promise marks from an OTLP capture server and waited for them — a direct violation of `everyday-tests-never-wait` A14, which forbids exactly that in the everyday tier. No phase's own verification caught it; only the whole suite at landing did, and the test was moved into `vitest.tiers.ts` SYSTEM to fix it. The retrospective's own words: "The third plan in a row where a whole-tree rule test went red only at landing" (following display-names' `lifecycle-single-definition.test.ts` A26 and release-records-its-failures' `head-sha-single-definition.test.ts` A19).

**How to apply:** this is no longer a one-off — it is a recurring, predictable gap in the per-phase verification step. The work skill should run every tree-scanning rule test (`*single-definition*.test.ts`, `everyday-tests-never-wait.test.ts`, and any other whole-tree-scan test) unconditionally at every phase boundary, alongside `vitest related` — they run in seconds, cheap insurance against a landing-time surprise. See also `whole-tree-scan-pins-are-invisible-to-vitest-related` for the first two instances.
