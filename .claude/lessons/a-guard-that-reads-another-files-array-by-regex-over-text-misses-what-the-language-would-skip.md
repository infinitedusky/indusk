# A guard that reads another file's exported array via regex-over-text (not import) counts a commented-out entry as live — import the module instead

test-kinds Build Phase 6 falsification, row A22 (`.indusk/planning/test-kinds/impl.md`): `everyday-tests-never-wait.test.ts`'s `adminSystem()` read the admin's `vitest.tiers.ts` `SYSTEM` array by regexing the file's raw text for `"(src/[^"]+\.test\.tsx?)"` strings. A line commented out of the array (`// "src/foo.test.ts",`) still matches that regex, so the guard believed the file was in the SYSTEM tier — exempt from the "no server starts, no clock waits" rule — while vitest's own `import { SYSTEM } from "./vitest.tiers"` (how `vitest.config.ts` actually builds its test list) would have run that same file as an everyday test. The guard and the thing it was guarding disagreed, and the guard's answer was the wrong one.

Fixed in `ef22f48e` by replacing the regex read with `await import(pathToFileURL(tiers).href)` and reading `mod.SYSTEM` directly — the same mechanism `vitest.config.ts` uses, so the guard can never see a different list than vitest does.

**Why:** any text-level parse of a source file (regex, line-matching, string search) only approximates what the language actually executes — comments, string escaping, conditional exports, re-exports, and formatting changes all break the approximation silently, usually in the direction of over-counting (something commented out, something inside a template string, something in a skipped branch). The file importing the data already has a correct, zero-maintenance parser: the runtime itself. This is a specific instance of the broader family in [[a-derived-fact-must-be-tested-against-the-artifact-the-deriving-system-reads-not-the-artifact-alone]] (System A produces an artifact, System B derives a fact from it, and only a test that runs B against A's *real* current output — not a hand-rolled second parser — can catch drift).

**How to apply:** when a test, hook, or guard needs to know "what does file X export" or "what list does module Y contain," and X/Y is importable (JS/TS, JSON, any module system with a loader), `import()` it — dynamically with `pathToFileURL(path).href` if the path is computed at runtime, statically if it's a fixed relative path. Reach for text-scanning only for genuinely non-executable artifacts (prose docs, config formats with no loader in this runtime, hook message strings). If you catch yourself writing a regex to extract values from a `.ts`/`.js`/`.json` file your own runtime could load, that's the smell.
