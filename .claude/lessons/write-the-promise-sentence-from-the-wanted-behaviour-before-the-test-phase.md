# Write a promise's sentence from the behaviour wanted before the test phase — rows can pass while pinning the opposite of the sentence, and fixing it afterwards costs the brief, the registry and a person's re-approval

In finished-rituals-stay-done, rows A5 and A8 passed while pinning "a skipped ritual reads skipped", but the accepted promise sentence said "a skip with a reason" reads done. The builder did not notice; a cold audit reading the sentence against the rows did. The fix took three steps: edit the brief, run indusk promises change for the registry, and get a person to re-approve (an amendment stops the build until then).

What to do: before Test Phase 1, write the promise sentence from the behaviour actually wanted, then check each row's assertion against the sentence word by word. A row that passes is not evidence it proves the clause. Change a promise through the promise-change tool, never by hand in the brief alone.
