# A "say it loudly" fix that only fails the run that created bad state is incomplete — it must also fail every later run while that state persists

watch-reopen-collision's falsification phase (A6, this plan's impl, archived at `.indusk/planning/archive/watch-reopen-collision/`) found that the plan's first fix was half of what it needed to be. The brief's original problem was `indusk promises watch` silently reporting success (exit 0) when an incident was opened but its owner never gained a Maintenance phase. The first fix made that *opening* run exit 1 — but once that run passed, the incident was left permanently unowned, and every subsequent `watch` run reported "No new violations" and exited 0, because nothing ever retried the reopen. The failure was silenced for exactly one run and then became invisible again.

The fix: a `watch` run now re-checks every open incident for whether its owner carries a Maintenance phase, and reports an `unowned` kind — retried on every run — until the owner actually gains the phase. `watchReport` (`apps/indusk-mcp/src/lib/promises/watch.ts`) treats `unowned` the same as a fresh collision for exit-code purposes.

**How to apply:** when fixing "a monitor silently reports success in situation X" by making the triggering run fail loudly, always ask the follow-up question: *what does the next run say, after the bad state this run created or revealed still exists?* If the answer is "nothing, because nothing re-checks," the fix only moved the blind spot one run later. The test plan should carry an explicit row for the run *after* the one that caused the bad state — this plan's own retrospective notes that falsification (not the test plan) is what caught this, and that writing that row at test-plan time would have caught it earlier.

See `.indusk/planning/archive/watch-reopen-collision/retrospective.md` ("What We Learned", "What We'd Do Differently") and `apps/indusk-mcp/src/lib/promises/watch.ts` (the `unowned` kind).
