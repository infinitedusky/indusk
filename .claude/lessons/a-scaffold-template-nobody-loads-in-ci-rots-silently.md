# A project scaffold/template that only runs in a user's generated project, never in this repo's own test suite, can ship broken for months with every test green

A template file (a scaffold `init` writes into new projects, a generated config, boilerplate meant to run elsewhere) is invisible to every test in the repo that produces it unless something actually instantiates a project from the template and loads the result. Code review, type-checking the template's own syntax, and even reading it carefully all miss a runtime break, because the template's code never executes anywhere CI touches — it only executes inside a project this repo doesn't build or run.

**Why:** browser-telemetry-leftovers (dusk, 2026-10-11, archived at `.indusk/planning/archive/browser-telemetry-leftovers/`). The browser telemetry template had been throwing `addSpanProcessor is not a function` against `sdk-trace-web` 2.x (the exact version its own install line fetches) and reading a bare `process` in a Vite page — for months, undetected, because nothing in the test suite actually scaffolded a project from the template and loaded it. Test Phase 1 only found both breaks because the plan finally built a real browser test project (`vitest.templates.config.ts`) that loaded the template for the first time. The retrospective's own words: "A template nobody loads rots silently."

**How to apply:** any template, scaffold, or generated-project boilerplate needs at least one test that actually instantiates it (scaffolds a throwaway project, installs its declared dependencies at the versions it names, and loads/runs the result) rather than only linting or type-checking the template's source in place. If no such test exists for an existing template, treat its current state as unverified regardless of how long it's been unchanged — "nothing changed" is not evidence it still works, only evidence nothing has tested it either way.
