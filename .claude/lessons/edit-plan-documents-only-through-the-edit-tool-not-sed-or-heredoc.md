# Edit InDusk plan documents (impl.md, brief.md, etc.) only through the Edit tool — a sed command or a Python heredoc writing the same file bypasses the PreToolUse gate chain entirely, and checking the result afterward is exactly the manual step hooks exist to make unnecessary

During dawn-workbench-execution's Build Phase 7, two impl.md edits were made via `sed` and a Python heredoc instead of the Edit tool. Both edits turned out to be legitimate under Gate A/B when checked afterward — but that after-the-fact check is the point: InDusk's PreToolUse gate chain (`check-gates.js`, `validate-impl-structure.js`, etc.) only fires on tool calls it's wired to inspect (Edit/Write), the same fact the existing `gate-covers-tool-surfaces-not-intentions` lesson records about `indusk run`'s bash-lane gate. A `sed`/Bash-heredoc write to the same file is invisible to that gate chain by construction, regardless of whether the resulting edit happens to be correct.

The distinction from the existing gate-coverage lesson: that one is about an *orchestrator's own automated loop* failing to route a tool surface through its gate. This is about a *working agent's own tool choice* — reaching for `sed`/Bash instead of Edit — opting out of gate coverage that the project already correctly wired for the Edit tool. The gate isn't broken; the agent routed around it.

How to apply: when editing any InDusk plan document (impl.md, brief.md, adr.md, test-plan.md, current.md), always use the Edit tool, never a shell one-liner or heredoc, even when the change is small or the shell approach seems more precise for a multi-line replace. "I verified it was fine afterward" does not substitute for the gate actually running — that verification is manual, one-time, and easy to skip under time pressure; the gate is automatic and cannot be skipped by forgetting.
