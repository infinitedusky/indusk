# An exemption keyed to a thing's latest record forgets what earlier records established — grant it per item and only on recorded evidence, and re-read every trajectory row about the exemption before rewording the rule

The component check exempted a mockup by the plan in its latest approval. Falsification found a re-approval by an in-flight plan dropped the whole mockup (five core plan-page mockups left the check); the audit found approvals with no recorded `components` did the same. The rule that holds (lib/looks/landed.ts heldComponentNames): only-in-flight-approved mockup is exempt (new); a landed approval that recorded components holds those; a landed approval that recorded none holds the mockup in full.

Second half: a Phase 6 plan item first said "no held approval → held in full", contradicting row A8 (an unlanded plan's new mockup is exempt, plan.master); it was caught only because the item told the executor to stop when real unimplemented components were reported. Before writing an item that changes an exemption, re-read every existing trajectory row about it.

Why: main-suite-green A8, A10, A12. Cited in apps/docs/src/lessons/main-suite-green.md.
