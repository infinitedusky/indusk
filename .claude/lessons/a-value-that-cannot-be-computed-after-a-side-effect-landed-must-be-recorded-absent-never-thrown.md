# "Nothing to attest" is a fact, not an exception — if a value can't be computed only AFTER the side effect it describes has already landed (e.g. a commit trailer naming a commit that turns out not to exist, like an unborn git branch), record its absence and continue; throwing after the effect already applied leaves the system in a state nothing can report or recover from

dawn-workbench-execution's `Code-Commit:` trailer (naming the code repo's commit sha in the plan-repo's checkoff commit) threw when the code repo was on an unborn branch (no commits yet, so no sha to name) — and it threw from inside a tool call, *after* the file edit it was trailering had already been applied to disk. The edit succeeded; the commit-with-trailer step failed; the caller was left holding an already-mutated working tree with no way to know from the thrown error alone what state things were actually in.

The fix follows the same shape as this project's existing "commit cadence failure is bookkeeping, never a gate" rule: a value that genuinely cannot exist yet (no commits = no sha to attest) is not an error condition, it's a fact about the current state, and it must be recorded as such (the trailer omitted, or the run report noting "no code commit to reference") rather than thrown.

How to apply: whenever code computes a value to *describe* a side effect that already happened (a trailer, an audit-log line, a commit message annotation, a report field), ask whether the value's absence is a legitimate state of the world (not yet exists, not yet computed, doesn't apply here) versus a genuine bug. If it's a legitimate absence, the function's contract must be "return/record nothing," never "throw" — throwing after a side effect has already landed produces an error that describes nothing actionable about the mutation that already happened, and forces the caller to somehow un-happen an edit that's already on disk. This generalizes past this specific trailer: any post-hoc-descriptive value computed after a mutating step is a candidate for this rule.
