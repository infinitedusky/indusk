# Write a brief's "Changes" entry for an existing promise as the exact new sentence, not a diff-style description — promises confirm matches it literally against the registry

In workbench-plan-authoring, a brief's "Changes" section for an existing promise was written as prose describing the change ("It becomes: …") rather than as the promise's new sentence verbatim. `promises confirm` compares a brief's Changes entry against the registry's sentence as an exact match, not a diff or a description of one — so prose like "It becomes: …" doesn't match anything in the registry and the command refuses.

Why it matters: this is the same category of mistake as writing a description of a value instead of the value itself — the brief's Changes section isn't a changelog entry explaining what happened to the promise, it's the literal replacement text the tooling will write to the promise file. A reader (human or `promises confirm`) has to parse "It becomes: X" to extract X, but the command does no such parsing; it expects the brief to already hold X.

What to do: when a brief's Promises section records a change to an existing promise, write only the new sentence itself — exactly as it should read in the registry after the change — never a description, diff, or "it becomes" framing around it.
