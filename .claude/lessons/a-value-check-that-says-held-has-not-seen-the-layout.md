# A look check by value says nothing about layout or state — a restyle is looked at (the page at phone width, each state opened), not only checked, and a state the check cannot open is reported unchecked, never held

**The rule.** `indusk looks check` holds an app by *values*: each foundation token on `:root` equals its approved value, and each measured property of each element is a member of the foundation. It does not see position, size or visibility, and it can only measure the page it is given. So a green check proves the app uses the approved values, not that it looks like the approved mockup. A restyle is also looked at: open the changed pages at the narrowest reference device, and open each declared state, before calling it held.

**Why it was learned.** ui-promises Build Phase 5 restyled the admin onto the foundation: `translate-x-0` compiled to nothing once Tailwind's spacing namespace was reset, the nav sat off-screen, and the check reported 33 of 33 looks held. A cockpit-phone test found it, not the check (impl Build Phase 5 Forward Intelligence; fix: `--spacing-0` in the generated theme). The same phase recorded that the admin ignores `?state=`, so eleven mockups were checked against three pages and 'every state of a screen measures the same page — the check says held for a state it did not open'.

**How to apply.** (1) After a restyle, add or run a layout-level test (an element is on screen, at the device's width) beside the value check; do not accept 'all held' as the restyle's evidence. (2) A declared state the check cannot reach should print and be recorded as `unchecked`, so the promise `every-part-of-the-ui-is-covered` never reads 'held' for a part nothing opened. (3) Dark values are emitted but not measured; say so wherever 'held' is claimed.
