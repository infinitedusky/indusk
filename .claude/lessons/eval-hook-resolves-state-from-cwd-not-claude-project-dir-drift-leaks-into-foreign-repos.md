# The eval-trigger hook resolves its InDusk state root (.indusk/eval/) by walking up from the session's cwd, never from CLAUDE_PROJECT_DIR — if a Bash command leaves the cwd inside an unrelated cloned repo, machine state gets written into that foreign repo instead of the actual project

`apps/indusk-mcp/hooks/_hook-paths.js`'s `resolveStateAndGitPaths(cwd)` derives both the InDusk state path (walk up from cwd to find `.indusk/`) and the git path (`git rev-parse --show-toplevel` against cwd) purely from the session's current working directory at the moment the hook fires — it never reads `${CLAUDE_PROJECT_DIR}`, the host-provided variable that names the actual project root regardless of where the session's cwd has drifted to.

Found 2026-09-16: `eval-trigger.js` wrote `.indusk/eval/system.log` into a scratchpad clone of an unrelated repo (`aeonfun/aeon`), because a prior Bash command in the session had `cd`'d into that clone and never `cd`'d back before a `git commit` fired the PostToolUse hook. The hook faithfully walked up from that cwd, found a `.indusk/` (or created one) in the foreign repo, and wrote InDusk's own machine state there — silently, with no error, since from the hook's perspective it did exactly what it's designed to do.

This is the same underlying cwd-relative-resolution problem the `hook-cwd-independence` plan (in progress as of this session) fixes for hook *command registration* (`node .claude/hooks/x.js` failing to load from a subdirectory) — but this is a distinct instance: even a hook that *does* load correctly can still resolve the wrong *state directory* if its internal path resolution trusts `cwd` over `CLAUDE_PROJECT_DIR`. Fixing hook registration alone does not fix this.

How to apply: when a hook needs to know "where does this project's `.indusk/` actually live," prefer `${CLAUDE_PROJECT_DIR}` (or an explicit passed-in project root) over walking up from `cwd`, especially for any hook that writes machine state as a side effect. If cwd-based resolution is kept for git operations specifically (finding the nearest git repo, which is a legitimate cwd-relative question), state-path resolution and git-path resolution should not share the same cwd-dependent function without an explicit guard against the two diverging. See `.indusk/planning/hook-cwd-independence/` for the sibling registration-time fix; this is the runtime-resolution half of the same class of bug.
