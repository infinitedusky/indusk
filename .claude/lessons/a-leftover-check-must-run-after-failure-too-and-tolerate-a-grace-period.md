# A cleanup/leftover guard chained with && after tests is skipped on exactly the runs most likely to leave leftovers — and a check reading one instant of the process list cries wolf on something still shutting down

test-daemons-never-leak's falsification pass found that Build Phase 1 wrote the leak guard chained after the test command with `&&` — which bash skips whenever the preceding command fails or crashes, exactly the runs most likely to leave an orphaned process behind. Separately, a guard that reads the process list at one instant can report a process still in the middle of shutting down as a leak, which — if not given a grace period — makes the guard cry wolf on clean runs until someone disables it.

**How to apply:** a guard whose job is "did this run leave something behind" must (1) run unconditionally after the subject command, success or failure — not via `&&` — the project's fix wires this through `with-daemon-guard.js` rather than the test script's own chaining; and (2) allow a short grace period before declaring a still-present process a leak, re-checking rather than failing on the first read. A guard that fails on healthy runs gets switched off, which is worse than not having one.
