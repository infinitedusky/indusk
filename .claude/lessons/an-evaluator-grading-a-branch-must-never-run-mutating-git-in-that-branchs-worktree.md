# The eval agent grading a branch ran `git stash` inside that branch's own worktree while the working agent had uncommitted edits — it silently took the agent's in-progress work along with its own current.md section; this is strictly worse than the port/lock collisions already seen and needs its own fix (a snapshot worktree, or no mutating git from the evaluator, ever)

During watcher-heartbeat (`.indusk/planning/archive/watcher-heartbeat/`), the eval agent — grading this branch's commits — ran `git stash` inside `plan/watcher-heartbeat`'s own worktree while the working agent had uncommitted edits in progress (reflog: "reset: moving to HEAD", stash `8d97ef80` at 20:22:07). The stash silently took the working agent's uncommitted impl edit and an uncommitted source change along with the evaluator's own `current.md` section — real, in-progress work vanished from the working tree with no warning. The same session, the evaluator also ran the admin's HTTP tests in that worktree, holding the always-on server's fixed port 16685 so `always-on-source` failed to start — the same class of collision already recorded in [[an-evaluator-grading-a-branch-runs-that-branchs-tests-in-the-same-worktree-as-a-concurrent-human-run]] from the immediately prior plan (test-daemons-never-leak), and this is the **third** plan in a row to hit some form of evaluator-in-worktree collision.

This is a materially worse failure than a port or `.next/` lock collision: a lock collision produces loud, visibly wrong test failures that get investigated; a `git stash` silently removes uncommitted work with no error at all — the working agent (or the person) would only notice if they happened to check `git status` and find their edits gone, and recovery requires knowing to look in the stash list and `git checkout` the affected files back out of it.

**How to apply:** an evaluator (or any automated agent) that is scoring, reviewing, or testing a branch must never run a command that mutates the working tree or index of the worktree it is evaluating — `git stash`, `git reset`, `git checkout --`, `git clean`, or anything that discards or hides uncommitted changes — regardless of whether the evaluator believes the tree is clean. If an evaluator needs a clean tree to run tests, it must do so in an isolated copy (a separate worktree, clone, or snapshot), never the shared worktree a human or another agent may be actively editing. This needs a structural fix, not a convention: either the evaluator always runs against a disposable snapshot, or the evaluator is denied any git subcommand beyond read-only ones (`status`, `log`, `diff`, `show`). Recorded as an open hazard in test-daemons-never-leak's retrospective ("Insights Worth Carrying Forward") and now confirmed to escalate beyond collision into silent data loss — not this plan's to fix, but it needs a plan of its own before a fourth incident.
