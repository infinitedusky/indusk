# The admin drives claude over an undocumented flag, and a contract test watches it — never change the session protocol without running it

The admin and the build runner start the developer's own `claude` with `--permission-prompt-tool stdio` and talk to it over its stream protocol: a question and a tool request both arrive as a `control_request` of subtype `can_use_tool`, answered by a `control_response`. That flag is the protocol under the official Agent SDK, but `claude --help` does not list it, so a Claude Code release can change it without notice. The Agent SDK was rejected because a published product must give it an API key instead of the developer's own login (admin-plan-authoring ADR, D1).

What to do: keep the protocol in `lib/session/protocol.ts`, pure and tested against exchanges recorded from a real session (`lib/session/__fixtures__/`). When Claude Code changes, record new fixtures from a real run rather than editing the old ones to fit. `session-protocol-contract.test.ts` runs the real CLI through a question, a write and an interrupt in the system tier, at landing and on release. If it goes red, the fallback is the Agent SDK with an API key, behind the same `lib/session` interface.
