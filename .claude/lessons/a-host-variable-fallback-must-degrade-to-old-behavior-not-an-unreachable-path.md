# When a fix depends on a host-supplied variable that might be unset, the fallback must reproduce the OLD (working) behavior, never a path that can't exist — read the shipped string as a shell would, not as you intended it

hook-cwd-independence fixed hook commands from a cwd-relative form (`node .claude/hooks/<name>.js`, which broke after any `cd`) to a project-root form using Claude Code's own `CLAUDE_PROJECT_DIR` variable. An intermediate version wrote `node "${CLAUDE_PROJECT_DIR}"/.claude/hooks/<name>.js` with no default — and on any host where Claude Code doesn't set that variable, bash expands the unset variable to empty string, producing `node "/.claude/hooks/<name>.js"` (leading slash, filesystem root): a path that cannot exist on any real project. Every gate silently went off everywhere on that host, which is worse than the original bug (at least the cwd-relative form worked from the project root).

The shipped fix adds the POSIX default: `node "${CLAUDE_PROJECT_DIR:-.}"/.claude/hooks/<name>.js`. When the variable is unset, `:-.` substitutes `.` (the invocation cwd), reproducing the *original* cwd-relative behavior — a real regression from a subdirectory, but never a guaranteed-nonexistent path. The new fix is strictly better than the bug it replaces in every case, rather than better in the common case and catastrophically worse in an edge case.

Rule: any fix that reads a host-supplied environment variable to build a path, command, or config value must have its fallback branch traced through by hand as if the variable is empty — not "probably always set" — and that fallback must reproduce a previously-working behavior, never construct a string that is guaranteed invalid (a leading/trailing slash with nothing between, an empty command, a URL with no host). Found by reading the shipped string as a shell actually expands it, not as the author mentally modeled it running.

See CLAUDE.md's Known Gotchas ("Hook commands are registered by the project root, never relative to the cwd") for the final, correct form; this lesson is about the failure mode of the version before the default was added.
