# A step list that reads "is falsify/cleanup/audit finished" from the plan's one current lifecycle position forgets a ritual finished before the plan reopened — derive each ritual's own finished-ness from its own files, keep position only for "where is it now"

When three independent facts (has falsify finished? has cleanup finished? has the audit run?) are all inferred from a single derived value (the plan's current lifecycle position — which phase it's "at"), reopening the plan for a later build phase breaks all three inferences at once: the position moves back to "building," so every reader that infers "ritual X is done because the position is past X" now reads all three rituals as not-yet-done, even though they genuinely finished earlier and nothing undid that work.

**Why:** finished-rituals-stay-done (dusk, 2026-10-16, archived at `.indusk/planning/archive/finished-rituals-stay-done/`). Seen directly on `plans-are-promises` (evaluated earlier this session): an audit-follow-up build phase reopened the plan, and the step list — reading each ritual from the plan's one lifecycle position — put Falsify, Cleanup and Audit all after that position, so all three read "not yet" despite having actually finished. The retrospective's own words: "A step list derived from one position forgets finished work the moment a plan reopens. Read 'finished' from the work's own files, and keep position for 'where is it now'." The fix reads each ritual's completion independently from its own evidence (a closed phase, a legacy falsification log, the existence of `audit.md`), not from where the position pointer currently sits.

**How to apply:** when a UI or gate needs to answer several independent "has X finished" questions about a document's lifecycle, do not infer all of them from one derived "current position" value — that value answers "where is it now," a single fact, and collapses the moment the document's position moves for any reason (including a legitimate reopening that doesn't undo prior work). Give each independently-finishable thing its own derivation from its own evidence in the files, and keep the single lifecycle position for only the question it's actually suited to.
