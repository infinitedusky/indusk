# The retrospective archives a plan's folder before landing finishes — any command that still needs to find that plan's files after archiving (by its pre-archive path, or at a historical commit) must check planning/archive/ too, or it will refuse a plan that just closed

Second occurrence of the same architectural gap in two days. First: `indusk plans reapprove` ran `git show <approval-sha>:.indusk/planning/<plan>/brief.md` using the plan's *current* path, but the retrospective had already archived it to `planning/archive/<plan>/` by the time reapprove ran — the brief lived at the pre-archive path at that historical commit, so the lookup failed (found on `finished-rituals-stay-done`, see [[reapprove-an-archived-plan-needs-it-moved-out-of-archive-first]]). Second: `indusk plans tests <plan> --landing` refuses an archived plan with "no impl.md for <plan>" — `resolveImplPath` never looks under `planning/archive/` at all, and the retrospective's Step 9 (archive) runs before landing's Step 10, so the landing test-set check `tests-never-make-us-wait` just introduced cannot run at the exact moment the skill calls for it. Found closing `tests-never-make-us-wait` on 2026-10-18.

**Why:** the plan lifecycle moves a plan's folder (`planning/<plan>/` → `planning/archive/<plan>/`) as part of closing, but that move happens *before* several things that still need to operate on the plan are finished — a brief re-approval, a landing test run. Every one of those lookups was written assuming the plan's current, pre-archive path, because that's where the plan lived while it was being authored and tested. Each is a separate function (`resolveImplPath`, the brief-at-sha lookup in `reapprove`) with the same blind spot, so fixing one does not fix the other — this is a class of bug, not a single bug, and a third post-archive lookup (anything new that runs at or after landing) is likely to have the same gap until the class itself is fixed.

**How to apply:** any function in `lib/` that resolves a plan's file path — current or historical — should try both `planning/<plan>/` and `planning/archive/<plan>/` (or resolve archival status first and route accordingly), not just one. `resolveImplPath` (apps/indusk-mcp/src/lib/impl-parser.ts, the single-definition pin per apps/indusk-mcp/CLAUDE.md) is the first and most central place to fix this once, since it's already a pinned, single-use resolver other code depends on — fixing it there may close multiple instances of the class at once. Until fixed, the workaround for `reapprove` is `git mv` the folder out of archive and back; for `plans tests --landing`, no workaround is recorded yet (found same day as this lesson).
