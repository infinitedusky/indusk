# A promise that an agent "won't do X" because the prompt says so is not held — if the agent has the tool to do X, code must confine it and telemetry must watch for it

An instruction in a system prompt or conversation setup ("only touch files in your draft," "don't run arbitrary commands") is not enforcement. If the underlying tool grant still lets the agent do the forbidden thing, the promise is held by the model's compliance that turn, not by anything that would catch or prevent a deviation.

**Why:** new-project-flow (dusk, 2026-10-14, archived at `.indusk/planning/archive/new-project-flow/`). The audit — a reader who had not seen the build — found three promises held "only because the prompt said so": the conversation's agent could in fact run any shell command, nothing in code stopped it. The retrospective's own words: "A promise held only by a prompt is not held. If an agent can break a promise, the code has to stop it (confinement) and telemetry has to watch it; an instruction is neither." The fix (Build Phase 7) actually confined the conversation's agent to its draft with a restricted tool set (Read/Write/Edit/Glob/Grep only) — removing the capability, not just asking the agent not to use it.

**How to apply:** when a brief or promise describes a boundary an agent must not cross, check what tools/capabilities that agent session is actually granted, not what the prompt tells it to do. If the capability to violate the boundary exists, either remove it (the preferred fix, as here — restrict the tool grant) or add telemetry that would catch a violation in production. A prompt instruction alone proves nothing about what will happen the one time the model doesn't follow it.
