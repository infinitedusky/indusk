# A cleanup/leak guard chained after tests with `&&` is skipped on exactly the failing or crashed runs most likely to leak — and a guard reading one instant of the process list reports a process still shutting down as a leak

dusk's test-daemons-never-leak plan (`.indusk/planning/archive/test-daemons-never-leak/`) built `check-test-daemons.js` to name any telemetry process still running from a temporary test home and fail the run. Two bugs surfaced only in falsification, after the happy path already passed:

1. **The `&&` skip.** Build Phase 1 wrote `pnpm test && node check-test-daemons.js` — ordinary shell semantics mean the guard never runs when the preceding command fails or crashes. A failing or crashed test run is the likeliest run to leave a daemon behind (cleanup code in a `finally` or `afterAll` may not run on a hard crash), and it was exactly the one case the guard silently skipped. The fix: `with-daemon-guard.js` wraps the test command and always runs the guard afterward, regardless of the wrapped command's exit code, and `pnpm test` / `pnpm test:system` both go through it.
2. **The instant-read false positive.** The guard's first system-tier run named a daemon that was gone a second later — a process a test had already told to stop, still in the middle of exiting. A guard that fires on a process mid-shutdown is a guard that cries wolf, and a guard that cries wolf is the one people switch off. The fix: re-check for five seconds and name only what is still running after the grace period.

**How to apply:** any end-of-suite guard whose job is to catch a leftover (a process, a lock file, a temp directory, an open connection) must (a) run unconditionally after the test command, success or failure — never chained with `&&` — and (b) tolerate a brief shutdown window before declaring something leaked, rather than trusting a single instant's state. Write both into the test plan's description of the guard up front ("report the leak, even when the tests fail") rather than discovering the `&&` gap in falsification — it's the obvious case, not an edge case.
