# A gate that treats every changed file under an app's component path as an "interface change" will wrongly refuse plans that only touch test files — a test file renders nothing a mockup must cover

A rule meant to catch "did this plan change how the app looks, without a corresponding mockup" needs to distinguish rendering code from everything else that happens to live beside it. If the rule's file-matching pattern is broad (e.g. "any file under the component scan's glob"), it will also match test files for those components — which is wrong, because a test file renders nothing a user sees and has no look to cover. A story file is correctly still caught, since it renders an approved snapshot a mockup must match; a test file never does.

**Why:** main-suite-green (dusk, 2026-10-15, archived at `.indusk/planning/archive/main-suite-green/`). `plans accept`'s interface rule (`interfaceFilesAmong`) counted four admin route test files as look changes, refusing acceptance. The retrospective's own words: "A test file is not an app's interface... The interface rule had been refusing every plan that touches an app's tests since brief-as-the-contract" — a systemic false-positive spanning multiple plans across this session, fixed almost as an afterthought at this plan's acceptance step (Build Phase 7, "added at acceptance"). The fix split a dedicated `isTestFile` check out of the component-scan pattern.

**How to apply:** when building a gate that scans a glob to decide "does this file need a mockup/look," explicitly exclude test files (and any other non-rendering file type that happens to share the glob) rather than trusting the glob alone to mean "this file renders UI." Any gate built on a broad path pattern should be tested against the kinds of files that commonly live beside the thing it's meant to catch — test files, snapshots, type definitions — not just against the positive case it was designed for.
