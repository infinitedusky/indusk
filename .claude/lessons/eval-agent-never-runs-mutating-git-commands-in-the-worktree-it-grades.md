# An eval/grading agent must never run mutating git commands (git stash, reset, checkout --) in the worktree it is grading — only read-only inspection (git show, git diff, git log)

During the watcher-heartbeat plan, an evaluator grading a commit ran `git stash` in the plan's own worktree while the working agent still had uncommitted work in progress — including an uncommitted `telemetry.ts` re-export an already-committed admin change depended on. This nearly lost that work; it was recovered only by checking files out of the stash commit. The retrospective (`.indusk/planning/archive/watcher-heartbeat/retrospective.md`, "What We Learned" / "Insights Worth Carrying Forward") flags this as having "cost three plans time and once nearly lost work" and calls for the evaluator to run against a snapshot and never run mutating git commands.

This is distinct from the resource-collision class already covered by [[evaluator-running-tests-in-the-same-worktree-collides-with-concurrent-runs]] (ports/locks/build caches) — this is about destructive git operations against another agent's in-progress, uncommitted state.

**Rule:** an eval agent inspects a commit via `git show <sha>`, `git diff`, `git log`, and read-only file reads. It never runs `git stash`, `git reset`, `git checkout --`, `git clean`, or any command that mutates the working tree or index of a worktree another agent may be actively using. If verification requires running tests/builds against the code at a specific commit, do so in an isolated copy (worktree/clone), never the shared one — and note this as still unbuilt as of 2026-10-03, so prefer the safest read-only check available rather than assuming isolation exists.
