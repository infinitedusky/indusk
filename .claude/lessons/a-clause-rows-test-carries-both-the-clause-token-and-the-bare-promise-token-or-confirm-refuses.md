# A clause row's test file carries both `clause: <promise>/<clause>` and the bare `promise: <promise>` token — the retrospective gate can say ready while `indusk promises confirm` refuses

In a-new-project-starts-instrumented the retrospective-readiness check reported the promises proven while `indusk promises confirm` refused 19 times: the tests carried only `clause: p/c` tokens (confirm also needs a bare `promise: p`), two rows named a clause their test file lacked, and state promises had no code token. The gate and confirm disagree about what proven means. Until the gate runs confirm's checks, /work must put both tokens in a test file when it writes a clause row's test, check that each row's named clause appears in its file, and give each state promise a code token; run `indusk promises confirm <plan>` (dry) before calling a plan ready for its retrospective.
