# Before citing a past plan's defect count or "X was impossible to find until phase Y" in new docs, grep that plan's own retrospective/impl — don't trust a round number that sounds plausible

A doc commit citing another plan's history as evidence (e.g. "dawn-verify is the evidence: two of its seven confirmed defects were structurally impossible to find before Phase 4") is making a checkable historical claim, not a rhetorical flourish. If the cited plan's own retrospective doesn't state that count or that phase-dependency anywhere, the claim is unverified at best and wrong at worst — and it's exactly the kind of clean, specific-sounding number that reads as authoritative without anyone checking it.

Seen in dusk: lifecycle-rebalance's falsification-ritual.md (commit 0684b081) states dawn-verify had "seven confirmed defects," two "structurally impossible to find before Phase 4." Checked against dawn-verify's own retrospective.md:81-82 ("Defects found after impl complete: 4... Defects found by falsification: 5 hypotheses, 5 confirmed" = 9, not 7) and impl.md's Phase 6 section (9 checklist items, none citing a Phase 4 code dependency — the two dogfooding defects actually trace to Phase 3's red-test detection, discovered by running the finished tool against a real monorepo, not because Phase 4's code needed to exist first). The claim doesn't match the source plan's own numbers or its own stated causation.

This is the fourth instance in one session of this pattern from the same agent: an extension count and prose-size figure stated with unwarranted precision (952e3244), a lesson name cited that doesn't exist (a829acd9), a "reverted" claim that never touched the file (6883e361), and now a historical defect count that doesn't match its own source document. The common failure: writing a specific, clean-sounding number or citation without grepping the artifact it's supposedly drawn from.

Before landing a sentence that cites another plan's numbers, dates, or causal claims as evidence: `grep` that plan's retrospective.md and impl.md for the actual figures, and quote or paraphrase what's really there rather than a remembered or approximated version. If the number doesn't appear verbatim, treat it as unverified and either find the real number or soften the claim to what's actually supportable.
