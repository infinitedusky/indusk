# Measure the no-change floor before writing a timing expectation — checks that can never complete are reopened every run and make a "cost proportional to change" promise unreachable

The looks-check-speed brief set a 15 s one-component and 60 s full-check expectation before anyone ran a check with nothing changed. About 40 looks in the checkout can never be checked (pages that do not report their state, fixture plans answering 404), and a look last unchecked is always reopened (A4), so a no-change run took 57 s and both expectations were missed (98 s full, 89-95 s one component) and had to be accepted as information. Run a no-change pass at research time and count what a run can never finish; if there is a fixed floor, fix or exclude those items first, or write the expectation above it. The floor was carried to looks-as-promises. See .indusk/planning/looks-check-speed/retrospective.md.
