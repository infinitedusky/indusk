# When code matches a name that another agent chooses (a recommendation, a key, a label), match by meaning or fix the name where it is chosen — a test fixture that uses the expected name hides the gap

disableDeclinedTelemetry in a-new-project-starts-instrumented turns telemetry off only for a recommendation named exactly `telemetry`, but the new-project prompt lets the agent write `"name": "<practice>"` with no fixed name. A decline named `observability` or `local-telemetry` would still enable both extensions and scaffold, breaking the must-not-break promise a-recommendation-can-be-declined; T20 passed only because its fixture used `telemetry`. Rule: when a consumer depends on a string a model or person picks, either fix the string where it is chosen (the prompt, a schema enum) or match by meaning, and write the test with a differently named input. Source: highlight h-20261017-029; audit.md finding on lib/new-project/prompt.ts.
