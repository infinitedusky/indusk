# Three costs that are cheap to pay upfront and expensive to discover mid-experiment: artifact preservation, telemetry, and blocking credentials

Three related hindsights from dawn-external-orchestrator's acceptance matrix (A8), each the same shape: a cost that was obviously payable on day one instead surfaced mid-experiment as expensive rework.

1. **Preserve run artifacts from day one whenever outcome quality will ever be judged.** The matrix reset state after recording each cell's summary, then later needed a real quality read (mutation testing) — forcing transcript recovery and re-runs to get artifacts that existed once and were thrown away. If a quality judgment is even plausible later, keep the raw artifacts from the first run.
2. **Build matrix-grade telemetry (per-attempt token usage, per-edit block counts) into the loop before running the matrix**, not hand-stitched around afterward. The loop only reported cost/step data on green phase close, so every red-stop attempt's cost was invisible — a gap that had to be worked around by hand for every failed cell instead of being solved once in the instrumentation.
3. **Chase a blocking credential as a Phase 0 checklist item, not an ambient hope.** The Claude driver sat completely unexercised for a week because getting an API key wasn't tracked as a concrete task — the eventual unblock took one paste. A dependency that blocks a whole experiment arm belongs on the checklist from the start, not in the background of "we'll get to it."

**The shared pattern:** each of these was knowable and cheap to address before the expensive work started, and each was instead discovered as a cost multiplier — re-runs, hand-stitching, or a week of idle capability — once the expensive work was already underway. When planning any multi-run experiment or matrix, ask explicitly: what artifacts will I wish I'd kept, what telemetry will I wish I'd built in, and what credential/dependency is silently blocking a whole arm — before starting, not after the first gap bites.
