# A fixture written in the format the code already expects proves nothing about real data — measure a data-derived rule against the project's own real records, in the phase that writes it

When a function derives output from parsing some real-world text convention (a changelog entry's `(plan-name)` parenthetical, a commit message format, a specific prose line), its unit test fixture is usually authored by the same person who wrote the parser — so the fixture naturally matches whatever shape the parser expects, and the test passes even when the parser is wrong about the shape real data actually takes.

**Case:** dusk's `display-names` plan (`.indusk/planning/archive/display-names/`) built `planDates`/`releaseOf` to find a plan's shipping release by matching changelog entries shaped `(plan-name)`. The unit tests used fixtures with that exact shape, so they passed. Run against the real repository's 347 changelog entries, only 52 were actually written that way — 79 of 94 landed plans read "not released yet" in production. A similar gap hit the "landed" date (fixtures had the "Landed on main at" line; 80 of 111 real archived plans predated when that line started being written) and the release-commit lookup it was later replaced with (pre-1.36.1 commits don't match `chore(release):`).

**The fix pattern:** write a one-line script that runs the new rule over the project's own real historical records (all plans, all commits, all changelog entries — whatever the rule claims to generalize over) and count how many come out wrong. This takes seconds and finds exactly the gap between "passes its tests" and "true of the data it will actually see." Do this in the phase that writes the rule, not later in falsification — three separate bugs in this one plan were each found only when someone finally ran the measurement against real data, and each had already shipped past its own green tests.

**When to reach for this:** any time code parses or infers structure from existing free-form artifacts (commit messages, changelogs, prose conventions, user-authored text) rather than data the code itself controls the shape of. If the fixture was typed by the same hand that wrote the parser, it is not independent evidence the parser is right.
