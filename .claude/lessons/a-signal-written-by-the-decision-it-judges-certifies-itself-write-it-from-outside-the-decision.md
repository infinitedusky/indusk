# A clause's signal must not be written by the decision it judges — a refused close that writes "upheld" certifies the next close; derive the report from a place the decision does not control

In mark-first, closing-signal.ts set broken = result.ok && half.refused.length > 0 and confirm.ts returns ok:false whenever a half refuses, so the close could only ever report upheld, including when it refused a clause for having no signal. The refused close then wrote the first upheld reports for verified-before-release and upheld-by-its-signal, and the next close passed on them. The plan's own falsification summary and an audit both named it; it shipped as follow-up 1 instead of a fix. Rule: a signal exists to fail where the code could not notice (ADR D6); if it is computed from the same refusal logic it observes, with the heartbeat passed as true, it is a restatement, not a proof. Write the report from outside the decision (for example from a landing or CI run that stopped a change, or from a check over what a later reader shows) and add a test row asserting no upheld span is written for a refused half.
