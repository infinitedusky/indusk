# Before merging a branch, revert any line you changed in current.md's shared (union-merged) region back to trunk's current wording, and apply your real update directly on trunk after the merge

Commit 870a0a04 in planner-promises reverted the `## Project (shared)` line for the planner-promises plan in `.indusk/current.md` from "closed 2026-10-05... Falsified 15, cleaned, archived" back to "next (brief and test plan accepted)..." — i.e. back to exactly what `main`'s copy of that line currently says (verified byte-identical via `git show main:.indusk/current.md`). The commit message: "its one line is applied on trunk after the merge, beside other sessions' unsaved notes."

Why: `.gitattributes` declares `.indusk/current.md merge=union` (confirmed), and CLAUDE.md documents that this strategy "merges concurrent appends" in the shared region any agent may edit. Union merge takes the union of lines present on either side of a merge — it does NOT replace a changed line with the newer version; if branch has line A' (an edited version of line A) and trunk still has the original line A (because another concurrent session hasn't touched it, or trunk simply hasn't merged yet), a union merge produces BOTH A and A' as two separate lines in the result, not a clean single update. The only way to land a "replace this shared line" edit through a union-merge file without creating a duplicate is to either (a) merge immediately so trunk and branch are back in sync before anyone else edits the region, or (b) make the branch's copy of the line match trunk's CURRENT copy before merging, deferring the real edit to a follow-up commit made directly on trunk after the merge lands — which is what this commit did.

How to apply: any time a feature branch edits a line inside current.md's `## Project (shared)` region (not just appends a new line), before merging, diff your branch's current.md against `main`'s current.md for that exact line. If trunk's copy has drifted from what you based your edit on (because another session committed to trunk's current.md in the meantime), do not just merge and hope union resolves it — revert your branch's copy of that line to match trunk's live copy, and apply your intended update as a separate commit directly on main right after the merge completes. This is lower-risk than relying on merge=union to deduplicate a replaced (not appended) line correctly.
