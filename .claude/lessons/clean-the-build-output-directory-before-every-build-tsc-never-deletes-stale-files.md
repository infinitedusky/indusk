# Clean dist/ before every build — tsc never deletes output for sources that were since removed, and `pnpm publish` packs whatever is sitting in the working tree

vscode-extension's retrospective found that a published release (1.67.0) shipped 33 compiled files in `dist/` whose TypeScript sources had since been deleted from the repo — including `tools/graph-tools.js`, compiled from code removed at 1.33.0, carrying a shell-injection vulnerability a security researcher had reported against that earlier version. The vulnerable code was gone from `src/`, so a source-level audit or grep would show it fixed — but the compiled artifact kept shipping in every release after, because `tsc` performs incremental/additive compilation: it writes output for what currently exists in `src/`, and never deletes a `.js` file in `dist/` whose corresponding `.ts` source no longer exists. `pnpm publish` (and the project's packaging step) packs whatever files are physically present in the working tree's `dist/`, not what the current `src/` would produce from a clean slate — so stale files silently ride along indefinitely once they've landed once.

**Why it matters**: this is a supply-chain/security defect class, not just a correctness one — removing vulnerable code from source does not remove it from what gets published, and nothing in a normal build-test-publish flow surfaces the discrepancy (the build exits 0, the new code's tests pass, the stale file is simply never looked at again).

**How to apply**: `rm -rf dist/` (or the project's equivalent clean step) before every build that precedes a `pnpm publish` / release, not just on a fresh checkout. Treat "a vulnerability was reported and the code was removed" as unconfirmed-fixed until you've verified the published package itself (e.g. `npm pack --dry-run` or unpacking the actual tarball) no longer contains the old compiled file — a source diff is not sufficient evidence that a published artifact changed. This is distinct from the existing `pnpm-build-can-silently-no-op` lessons (a build that fails to rebuild fresh output) — here the build succeeds and rebuilds everything current, the problem is what it leaves behind from before.
