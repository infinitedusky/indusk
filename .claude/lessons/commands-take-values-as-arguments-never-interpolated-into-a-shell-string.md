# Every command run with an external value (person input, manifest, network) takes it as one argument array element — never interpolated into an execSync/shell-string template

The clean-release-build plan's research (apps: indusk-mcp) found ten execSync call sites that build a shell command by interpolating a value into a template string: `npm pack ${pkg}`, `curl -sf "${url}"`, `claude mcp remove -s project ${name}`, an eval task's `baseline: ${taskName}`, and a build-time `du -sk "${dir}"` in extensions.ts, eval.ts and bundle-admin.js. Each value originates outside the code — a person's CLI argument, a third-party extension manifest's MCP server name, a registry entry — so a value containing `;`, `$(…)`, or quotes is interpreted by the shell instead of passed through as text. This is the same vulnerability class (CWE-78) as the graph-tools injection a security researcher reported, just in different call sites — the researcher's report was about dead code; these are live.

**Why it matters**: `execSync('cmd ' + value)` and `` execSync(`cmd ${value}`) `` are shell-injection-shaped regardless of how trusted the value looks today — an extension's manifest, a registry package name, or an eval task name are all attacker-reachable inputs in some flow (install a malicious extension, publish a malicious package name, etc).

**How to apply**: when a command needs a value that isn't a hardcoded literal, pass it as an array element to `execFileSync`/`spawnSync` (or the project's equivalent), never build a string for `execSync`/`shell: true`. The project's two exceptions are a project's own config-defined command and a hook's fixed command — those are commands the project authored, run as written, not values. New code: a build-time check (A8 in this plan's test-plan.md) should fail on any new template-string shell command with an interpolated value.
