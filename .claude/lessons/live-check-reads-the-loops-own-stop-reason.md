# A live check of an unattended loop reads the loop's own stop reason, not only the outputs it left behind

Why: in the live check of a-brief-is-planned-unasked, the working agent reported "stopped for approval" from the documents' state and its own checks. It had not read the run's own stop reason. The run had actually stopped "cannot-continue" because induskMcpPackageRoot resolved a wrong folder inside the admin's bundle (apps/apps/indusk-mcp/dist/lib). The outputs looked like a clean stop; only the loop's own reason showed the failure. How to apply: when a live check drives an unattended loop (planning runner, build runner, indusk run), read and quote the stop reason the loop itself reports before claiming how it ended. Outputs alone cannot tell a clean stop from a failure that left similar files. Highlight h-20261019-002 (correction, 2026-10-19). Related: "Record a live check in the last phase that changes its subject".
