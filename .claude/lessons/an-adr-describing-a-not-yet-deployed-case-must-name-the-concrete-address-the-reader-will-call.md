# An ADR that says "the deployed server's intake, with its credential" without naming where that address comes from leaves a config key undiscovered until mid-build — write the reader's actual call (the config key, the literal URL shape) before accepting the decision, not after

During watcher-heartbeat (`.indusk/planning/archive/watcher-heartbeat/`), the accepted ADR's D1 decision said a probe reaches "the deployed server's intake with its credential" — but the existing `promises.jaeger` config block had no intake/OTLP address, only a query URL and a credential for reading. The missing `promises.jaeger.otlp_url` key was discovered mid-build (Build Phase 1), not during ADR review, and had to be added as an unplanned addition to the config schema.

Two related hindsights from the same plan's falsification and build: (1) commit every file an item's checklist line touches before checking that item off — a `WatcherBlind` re-export needed in the admin package was missed from the commit for the item that added it, and only surfaced because the evaluator's `git stash` incident (see [[an-evaluator-grading-a-branch-must-never-run-mutating-git-in-that-branchs-worktree]]) exposed the gap; a checked-off item with an uncommitted file is indistinguishable from a complete one until something else forces a look. (2) give a timed/bounded operation (a timeout, a retry window, a wait) its caller's actual budget from the first draft, not a number chosen in isolation — the probe's 5 s wait was written without reference to the admin's own 2 s HTTP timeout budget, and the mismatch was only found in falsification, not in the original design.

**How to apply:** when an ADR's decision references a resource, address, or credential for a case that is designed but not yet built or deployed (here: "the deployed server," which did not exist yet), write out the literal form the reader's code will use to reach it — the config key name, the URL shape, which existing type it extends — as part of the decision, not as an implicit detail left for the build phase to discover. If that address genuinely can't be known until deployment specifics are settled, say so explicitly in the ADR's Open Questions rather than asserting the case is handled. Separately: when checking off an impl checklist item, verify every file the item's description names is actually committed, not just the primary one; and when writing a timeout/retry budget for code that will be called by another component with its own budget, check that caller's existing budget before picking a number.

See `.indusk/planning/archive/watcher-heartbeat/retrospective.md` ("What We'd Do Differently" / hindsight).
