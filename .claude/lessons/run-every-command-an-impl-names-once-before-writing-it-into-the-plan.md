# Run every command and path shape an impl names once before writing it into the plan — a command reasoned on paper (a script's argument forwarding, a report's file-name base) can be wrong in a way only running it shows

In release-records-its-failures the impl named `pnpm -w test:system -- --passWithNoTests {files}` as the rerun form, and assumed JUnit file names are repo-relative. Neither was run until Build Phase 5: the root `test:system` is an `sh -c` that never reads its arguments, so the form reran every file; and vitest writes package-relative names, so every real failure would have matched no trajectory row and routed nowhere. Both were found only because the build phase ran them (a one-file run took 1.2 s and wrote a report; a report name was compared with a row).

Rule: before an impl item names a command, a flag form or an output path shape, run it once (on one file, in a temp dir if needed) and write what it did into the plan. Applies to ADR examples too: amend the ADR when the run contradicts it. See `.indusk/planning/release-records-its-failures/retrospective.md` and `lesson: a-pnpm-filter-command-naming-a-package-that-doesnt-exist-exits-0` for the narrower filter case.
