# When work expands past what the brief and ADR scoped, amend them or ask — don't let the new behaviour ride along under an existing promise's row

plan-review-subagent's Build Phase 2 wired the admin build to run every step on its tier's model — even though the approved impl's Out of Scope section explicitly listed "the admin's Build button passing a model" as a future follow-up, and the ADR still says "the admin needs no change." The work was real and wanted (Sandy asked for it mid-build: "a plan can have models for the phases and them actually get used"), but it landed as a new trajectory row (A14) claimed under the pre-existing must-not-break promise `each-phase-runs-on-its-model`, rather than as a declared change to the brief/ADR's scope. The plan's own audit (question 3, "what does the code do that the brief never promised?") caught this as a discrepancy between the shipped code and the approved planning documents.

Why this matters: a promise's row is supposed to prove that promise's sentence, not quietly absorb unrelated new behaviour just because it touches the same code path. When a scope expansion rides an existing row instead of being declared, the plan's own documents (brief Out-of-Scope, ADR's stated non-goals) go stale relative to what was actually built, and nothing forces anyone to notice — only a fresh reader auditing the diff against the brief would catch it, which is exactly what happened here.

How to apply: when a user asks for something mid-build that the brief explicitly scoped out or the ADR explicitly declined, don't fold it into an existing checklist item or claim it under a promise that doesn't actually describe it. Either (a) amend the brief's Out-of-Scope / ADR's stated decision inline, recording the date and who asked, or (b) treat it as new scope requiring its own promise/row, or (c) ask the user to confirm the scope change explicitly before proceeding. The goal is that the brief and ADR stay an accurate record of what was decided, not a record of what was decided *before* the build started.
