# A deliberate cross-language port whose docblock names the function it mirrors can still diverge on what happens when the input is absent — read the two implementations side by side, not just their names

context-tiers' cleanup phase (Build Phase 8) found that `hooks/_hook-paths.js`'s `declaredRepoDirsAt` — a JS port of the TypeScript `resolveReposRoot`, with a docblock explicitly naming `resolveReposRoot` as what it mirrors — read an *absent* `repos_root` config value as the workbench root. `resolveReposRoot` itself reads an absent `repos_root` as the workbench's **parent** directory. The port's docblock correctly named its source of truth; the port's handling of the one unstated case (nothing declared) silently picked the wrong default. In a workbench with no declared `repos_root`, the hook judged the declared repo's root `CLAUDE.md` as living somewhere it didn't, misjudging it as nested rather than root.

This was found by reading the TS function and its port side by side while renaming what the port claimed to mirror — not by a test, not by a type system (JS has none here), and not by the docblock itself, which was accurate about *what* it ported and silent about whether the port actually matched on every branch. A single-definition-count test (exactly one `resolveReposRoot` in TS) cannot catch this, the same gap [[when-two-lanes-read-the-same-config-key-pin-that-they-read-the-same-key]] names for a renamed key — but this is a different failure: not a rename drifting the two lanes apart, but the port being wrong from the moment it was written, on the specific branch (the absent/default case) that's easiest to skip when translating logic by hand.

**How to apply:** when authoring or reviewing a deliberate twin-language port (TS/bash, TS/JS-hook, any pair that can't share an import), do not accept "the docblock says what it mirrors" as evidence the port is correct. Explicitly enumerate the source function's branches — especially the absent-input / default-value branch, which is the one most likely to be implicit in the original and therefore invisible when re-typed by hand — and write a test (or at minimum a side-by-side read) that exercises that exact branch in both lanes. The default case is where a faithful-looking port is most likely to be silently wrong.
