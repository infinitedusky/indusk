# A closing check that counts passing rows against a promise proves the bookkeeping is in order — not that anything actually tests the promise, until the row's test file carries the promise's token

A rule like "a promise closes when every clause has a passing row" checks the document's own records — row states, counts, labels — not whether any of those rows' underlying tests actually exercise the promise. "Passing" is text written in a markdown table; it can be true while the referenced test file does nothing related, or doesn't carry the token the closing rule actually keys on.

**Why:** plans-are-promises (dusk, 2026-10-16, archived at `.indusk/planning/archive/plans-are-promises/`). The retrospective's own words: "A closing check that counts rows proves bookkeeping, not testing: 'passing' is text, and until the test file carries the clause token, a clause can read proved while nothing tests it." The fix narrowed the gap by requiring the test file itself to carry a `clause: <promise>/<clause>` token (not just the impl's row saying so) before a clause counts as proved — but the retrospective is explicit that the remaining gap closes only once `mark-first` lands proof-by-signal (the running system's telemetry, not a row's text, as the actual proof).

**How to apply:** when building or extending any "this promise/clause is proved when its rows pass" mechanism, distinguish three levels of confidence: (1) the row's `State` column says `passing` — proves nothing but that someone or something set that text; (2) the row's test file exists and is runnable — proves the row isn't fictional; (3) the test file itself carries the exact token the closing rule keys on and genuinely exercises the described behavior — the only level that proves the promise. Prefer closing rules that check level 3 (a token read from the actual test file content) over level 1 (trusting a hand-set or script-set row state), and recognize that even level 3 is still a static proxy until a system is watched in actual use.
