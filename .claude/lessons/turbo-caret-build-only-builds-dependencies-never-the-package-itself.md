# Turborepo's `^build` dependency only builds a package's dependencies, never the package's own dist — a test gated on "the build exists" can pass by silently skipping on a clean checkout

In a Turborepo pipeline, a task declaring `"dependsOn": ["^build"]` only guarantees that a package's *dependencies* have been built first — it says nothing about whether the package's own `build` task has run. A test suite that uses `describe.skipIf(missing build)` to gate tests needing the CLI's built output (`dist/`) will silently skip every such test on a clean checkout, because nothing in the pipeline actually built that package before its own tests ran.

**Why:** main-suite-green (dusk, 2026-10-15, archived at `.indusk/planning/archive/main-suite-green/`). The cold audit found that on a clean checkout, every `indusk-mcp` test needing the built CLI skipped silently — including A1, the only row proving the contract-stdin promise. Nobody noticed because a skipped test and a passing test both exit green. The retrospective's own words: "`describe.skipIf(missing build)` plus turbo's `^build` is a silent skip. `^build` builds dependencies, not the package's own dist, so a promise's only test can pass by never running." The fix: `turbo.json` now builds `indusk-mcp` before its own tests run, closing the gap.

**How to apply:** if a test file conditionally skips based on whether a build artifact exists (`fs.existsSync(distPath)` or similar), that pattern is a trap in any Turborepo pipeline unless the task explicitly depends on its own package's `build` (not just `^build`). Audit every `skipIf`/`skip`-based gate in the test suite for this exact shape, and prefer making the task's own `build` a real dependency over trusting `^build` to have produced it as a side effect.
