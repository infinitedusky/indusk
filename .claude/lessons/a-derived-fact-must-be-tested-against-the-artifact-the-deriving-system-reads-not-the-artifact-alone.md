# When one system (a scanner, a state deriver) reads a fact out of another system's artifact (a hook's refusal string, a register row), a test that only exercises the artifact-producing system proves nothing about whether the deriving system can actually read it

context-tiers' falsification phase (Build Phase 7, trajectory rows A18 and A19) found this directly: A6, an existing test, asserted that `check-gates.js`'s refusal prints the line naming `lesson: test-red-at-earliest-writable-phase` — and passed. Separately, `lessonStates` (the scanner that derives whether a lesson is "guarded" or "advisory" for `list_lessons`) read that same lesson as **advisory**, guarded by nothing, because the token's opener sat right after a `\n` escape inside the hook's string and the token grammar's opener regex didn't accept that position. A6 tested that the artifact (the hook's message) was correct. Nothing tested that the derivation (the scanner reading that artifact) actually worked. Both were "tested" in isolation and both reported success while disagreeing with each other — the project's own guarantee ("a lesson an enforcer holds reads as guarded") was silently false for this lesson the whole time A6 was green.

The same root cause produced a second instance in the same phase: A19 found that two register rows named an `enforcer` file that didn't actually carry a readable `lesson:` token — the register's claim and the scanner's ability to verify that claim had drifted apart, and nothing checked the claim back through the system that was supposed to make it true until A19 was written.

This is a distinct member of the "two things that must independently agree" family alongside [[a-positive-result-shows-a-mechanism-ran-not-which-mechanism]] (one observation can't prove *which* mechanism produced it) and [[when-two-lanes-read-the-same-config-key-pin-that-they-read-the-same-key]] (two single-source-of-truth lanes can silently diverge on a rename). The shape here is specifically: System A produces an artifact; System B derives a fact by reading that artifact; a test of A's output and a test of B's behavior, run separately, can each be green while B silently fails to read what A produced.

**How to apply:** whenever a scanner, state-deriver, or validator is supposed to read a fact out of another system's output (a hook's message string, a config file, a register row, a log line), do not trust a test that only checks the producing system's output looks right. Write a test that runs the deriving system against the real, current artifact and asserts the derived fact — the same test shape A19 took: read each register row's claim, then verify it through `lessonStates`, not through a second hand-rolled parser of the same tokens. If the two are tested through different code paths, they can quietly drift, and the drift is invisible until something greps the live derivation.
