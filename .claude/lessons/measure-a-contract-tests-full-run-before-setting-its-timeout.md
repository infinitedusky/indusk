# A slow contract check's timeout must be set from a completed full run, not from a run that was only ever observed stopping early

storybook-components' Maintenance phase found A18 (a contract test running 113 stories under `next dev`) had a 580-second timeout that had never actually been validated — every prior run had stopped early (on `message.you`) before reaching the full 580s budget, so nobody had seen what a complete run actually costs. When the earlier failure was fixed and the test could finally run to completion, it took 1,665 seconds — nearly three times the configured limit.

**Why:** a timeout written against a run that never finished is a guess dressed as a measurement. `measure-the-no-change-floor-before-writing-a-timing-expectation` (looks-check-speed) already covers the adjacent case — measuring a floor before writing an expectation in a brief — but this is the sharper, specific failure mode for test *timeouts*: a budget silently never gets exercised end-to-end because something else has always truncated the run first, so its number goes unchallenged for as long as that other failure persists.

**How to apply:** when setting or reviewing a slow/contract test's timeout, confirm at least one run has actually reached completion under that budget — not merely that it hasn't timed out, if an earlier assertion failure or exit would have stopped it first regardless. If the test has never finished a run, measure a full completion before trusting its limit, the same way `measure-the-no-change-floor` requires measuring a no-change pass before writing a speed expectation.
