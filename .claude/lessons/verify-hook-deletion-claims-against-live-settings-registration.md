# A hook "deleted in cleanup commit X" claim must be checked against git log --diff-filter=D and the live settings.json registration, not assumed from a commit message

dawn-hook-parity's research.md claimed `check-plan-order.js` "was deleted in the context-beam cleanup (62186774, 'cleanup dead apps')," correcting the Dawn master plan's hook count from 6 down to 5. This claim is factually wrong on ground-truth verification: `git show 62186774 --stat` shows `.claude/hooks/check-plan-order.js` being **added** in that commit (part of restoring/re-scaffolding `.claude/hooks/` after removing dead `otel-test`/`otel-test-v2` app copies), not deleted. `git log --all --diff-filter=D -- "**/check-plan-order.js"` returns zero delete events across all of history. The file exists on disk today at `.claude/hooks/check-plan-order.js`, and is actively registered as a PreToolUse hook in `.claude/settings.json:266` (`node .claude/hooks/check-plan-order.js`).

**What went wrong:** the research read a commit message ("cleanup dead apps") and a stat line showing large deletions in that same commit (from `otel-test`/`otel-test-v2` dead-app hook copies) and attributed a different file's continued absence to that cleanup, without running the specific diff-filter=D check for the file in question or checking whether it's still registered in settings.json today.

**The check that would have caught it:** `git log --all --diff-filter=D --name-only -- "**/{filename}"` shows every delete event for a specific file across all branches — if it returns nothing, the file was never deleted, regardless of what a nearby commit's message claims. Cross-check against the live settings.json/manifest registration as the final ground truth, since a file can exist on disk but be unregistered (dead) or vice versa.

**Why this matters beyond this one plan:** this is the same failure class as the existing `community-brief-author-bias-ground-truth-verification` lesson (ground-truth-verify every "X already works" claim before acceptance) — but inverted: here the false claim was "X no longer exists," which is just as load-bearing, since dawn-hook-parity's entire scope was built on the assumption there were only 5 hooks to reach parity with, silently excluding a 6th (arguably more, since check-plan-order is project-local and not package-shipped) live, registered gate from the parity work entirely.
