# A manual survey of "how many copies of this pattern exist" undercounts — run a script, not a reading

When an ADR's sequencing or risk argument depends on a fan-out count ("this pattern is duplicated in N places, so consolidate first"), get that count from a script that greps/parses the source, not from reading through files and counting by eye. A manual survey reliably misses structural siblings that are different enough in shape to not look like "the same thing" on a skim.

**What happened:** `test-phase-structure`'s ADR argued that the phase-heading regex existed in seven places and had to be consolidated into one definition before a second heading kind could safely be added — a real and correct danger. The count was wrong: there were nine. An eighth copy was a phase-*reference* regex (a structural sibling different enough in shape to slip a manual survey looking for phase-*heading* patterns), and a ninth was an entire second trajectory-row parser, both hiding inside `check-gates.js`. Neither missing copy was found by re-reading the code — both were found because something silently stopped working (see [[pin-deliberate-duplicates-with-a-count]] for the divergence-detection side of this same incident).

**Why it matters:** the fan-out estimate isn't a detail — in this case it was the number the plan's entire phase sequencing was built on. An undercount doesn't just misstate a number; it means the "consolidate everything first" phase ships with siblings still uncosolidated, silently reopening the exact hazard the consolidation was supposed to close.

**How to apply:** before writing an ADR or a plan phase whose safety argument rests on "there are N copies of X," write a one-off script (grep with a broad-enough pattern, or a proper AST/regex scan) that counts them mechanically, and treat any manual list as a lower bound to be checked against the script's output — not the other way around. Widen the search pattern deliberately to catch structural siblings (reference regexes next to heading regexes, a second parser next to the first), not just literal copies of the exact snippet you have in mind.
