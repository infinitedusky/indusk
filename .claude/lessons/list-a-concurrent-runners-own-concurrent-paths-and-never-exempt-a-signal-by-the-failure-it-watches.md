# A plan for a concurrent runner lists its own concurrent paths (tick vs loop, long step vs launches, shared files); and a signal's exemption, source or file list must not coincide with the failure it watches

Why: run-the-graph's concurrent runner was planned without a step listing where it races itself: the host's tick and the run loop both picked the same ready phase, a merge check longer than a minute held up launches, two undeclared phases with no declared files ran at once, and two phases appended to one shared doc and conflicted on every try. Its signals also failed in the same cases as the failures they watch: the ready-phases signal exempted a build whose record read stopped (which is what an admin restart produces), overlap was expanded only against files that already exist (most new files match nothing), and phase tips were read only from branches that can be deleted before the next check.

What to do: (1) for any runner that can act from more than one trigger, write a list of every pair of paths that can run together and name the serialising rule for each, with a row that races them. (2) For each signal, ask "in the case where this clause fails, does the signal's exemption, source or input still exist?" and change it if the answer is no: read from history that cannot be deleted, expand declared paths without requiring the files to exist, and never exempt a state that the failure itself produces.
