# A Deferred Verification mitigation wrapped onto multiple lines reads as "vague" to the retrospective audit — write it on one line

`auditPlanAtClose` / `classifyMitigation` (apps/indusk-mcp/src/lib/trajectory/audit.ts) classifies a Deferred Verification row's mitigation text by matching patterns against `row.mitigation`. During context-tiers' retrospective (2026-10-02), two rows' mitigations (U1: "the loading probes run before each release, and a red probe blocks it"; U2: a per-retrospective review) were flagged `vague` by the audit even though both are concrete procedures — because the mitigation text was wrapped across multiple lines in the impl.md source, and the classifier only matches/reads the first line. Collapsing each to a single line made both classify correctly. Separately, the same audit pass classified a procedure that happened to mention the word "plan" as `downstream-plan` rather than as the procedure it actually was.

**How to apply:** when writing or editing a Deferred Verification row's `mitigation:` field, keep it on one line even if long — wrapping it for readability in the source markdown will cause `auditPlanAtClose` to silently misclassify it as vague at the next retrospective. If the audit reports a mitigation as vague or misclassified, check whether the text is wrapped before concluding the mitigation itself needs rewriting. The underlying classifier bug (first-line-only read, naive "plan" keyword match) is not yet fixed — this is a workaround until it is.

See `.indusk/planning/archive/context-tiers/retrospective.md` ("Deferred Verification Audit") and `apps/indusk-mcp/src/lib/trajectory/audit.ts` (`classifyMitigation`).
