# Audit — plan-cockpit

## Does each row prove its promise's sentence, or something narrower?
- `apps/indusk-mcp/src/lib/promises/standing.ts:130` — `every-promise-is-listed` / A40 (trajectory row asserting the dashboard's thirty days count days and held plus broke never exceeds 30). `held` is `30 - brokenDays` whenever the promise has any activity or any heard row, so days nothing was observed read as held, and with production unreadable (`lastActivity` null, `heard.length` > 0) the dashboard still prints "held N". A40 proves the sum is at most 30, not that held days were held. The promise page (`proof.ts:258-292`) shows held from the store's marks, so the two surfaces can disagree on the same promise. Verified in code; no test compares them.
- `apps/indusk-mcp/src/lib/promises/standing.ts:113` vs `apps/indusk-mcp/src/lib/promises/proof.ts:258` — the dashboard window is a rolling 30 x 24 h from now; the promise page's is 30 UTC calendar days ending today (`today - 29 days`). A break heard on the calendar day 30 days back can count on the dashboard and be absent from the page. A41 (row asserting alias-name violations are counted on the page as the dashboard counts them) does not cover the window edge. Verified by reading both; moderate confidence it bites in practice.
- `apps/indusk-mcp/src/lib/promises/standing.test.ts:137` — `the-editor-shows-the-same-health-as-the-admin` / A33 (row asserting dashboard, promise page and `indusk promises status` report the same state). The test compares `standingOf`'s per-source health to `healthRows` inside the package. It never runs `indusk promises status`, the dashboard page or the promise page, and the page and dashboard make separate health reads (`promises/page.tsx`, `proofOf`'s own `readHealth`). Narrower than the sentence.
- `apps/indusk-admin/src/lib/stamp.test.ts:1` — `display-names-are-defined-once` / A43 (row asserting one `stamp` and that seven copies of the slice-and-replace read it). The test only checks `stamp` on two inputs; nothing asserts the copies are gone, and `cockpit-single-definition.test.ts` does not list `stamp`. The promise says these are worked out "in one place in the package"; `stamp` is defined in `apps/indusk-admin/src/lib/stamp.ts:8`, in the admin. `components/Scorecards.tsx:286` still formats a time its own way (outside the cockpit pages, but the same dashboard-to-timeline reading A43 names).
- `apps/indusk-admin/src/app/p/[project]/cockpit-phone.test.tsx:128` — `the-nav-fits-a-phone` / A7 (row asserting no page scrolls sideways at 400 px). Covers three pages: plan, dashboard, promise. The promise says "no page"; scorecards, research, and the plan page's collapsed Details tables/long file paths in non-fixture content are untested. The drawer and collapse parts (A6, A8) are real-browser and hold.
- `apps/indusk-admin/src/lib/decisions.test.ts` — `decisions-wait-in-one-place` / A15 and A16 (rows asserting an answer reaches the running agent "and it carries on", and a reply reaches the agent whether or not a session runs). Both use fake session objects; "carries on" is not observable there. `decisions.ts:141` starts a new session for a reply when none is "ours", but `session/manager.ts` allows one session at a time (same constraint `build-host.ts` and the fix route cite), so a reply while a session for a different plan runs throws and answers 409; A16's "whether or not a session is running" is narrower than "for it".
- `apps/indusk-admin/src/lib/decisions.ts:124` — the answer to a question is sent as `{ [waiting.decision]: answer }` for the first question only (`waiting.ts:87` keeps `questions[0]`). A multi-question `AskUserQuestion` gets one answered and the rest unanswered. No row covers a question with more than one entry.
- `apps/indusk-mcp/src/lib/plans/waiting.ts:115` — A13 (row asserting plans asked, awaiting approval and at review are listed, a plan waiting on nothing is not). "Approval" is any impl with status `draft` whose earlier documents are accepted; a plan whose agent is still writing the draft impl is indistinguishable, so it can be listed under Needs you before it is ready. The row's "waiting on nothing" fixture does not include a draft impl being written.
- `apps/indusk-admin/src/lib/build-host.release.test.ts:59` — A37 (row asserting a plan no longer waits on review once the release starts). The test reads `buildState().stop`, not `planWaiting`/`readWaiting`, which also consult the on-disk position (`waiting.ts:108-112`). The claim about the card is inferred, not asserted.
- `apps/indusk-mcp/src/lib/promises/proof.ts:152` — `a-promise-page-shows-its-proof` / A29 (row: the page says the tests miss the case when broken while every test passes). "Every test passes" is every row's `state` column reading `passing` in an impl (`rows.every(r => r.state === "passing")`), i.e. a document's claim, not a run; and a broken promise with no rows says nothing (`rows.length > 0`). The promise sentence is satisfied for the documented-passing case only.
- `apps/indusk-mcp/src/lib/promises/standing.ts:160` — `every-promise-is-listed` / A18 (row: dashboard lists every promise in the registry). `readStanding` reads the `partial` registry when entries are malformed, so a malformed promise is not listed (it appears only in the problems block). "Every promise in the project" is narrower for malformed files.
- `apps/indusk-admin/src/components/Promises.heard.test.tsx:99` — the earlier incident-recording row that said a count is "marked as of when the admin last heard" while production is unreadable was rewritten to "beside the banner"; `grep "as of"` over `Promises.tsx`/`PromiseProof.tsx` finds nothing. The "as of" marker was dropped. `the-admin-keeps-what-it-heard` is a Changes promise, so the change is permitted, but no row says the marker is intentionally gone.

## Which rejected ADR alternative does the code quietly take?
- `apps/indusk-admin/src/lib/promise-dashboard.ts:78-130` — ADR "Derive in the admin's `lib/`" (rejected: the editor and stage 2 need the facts, and the admin's `lib/` keeps only fs-to-props glue). `buildRows`, `pathOf` (which Path declares a promise's plan), `filterRows`, `groupRows`, the `compare` order that puts broken first, and `standingCounts` are derived facts computed in the admin. A34 (row asserting the cockpit's facts are defined once in the package) searches for named functions (`standingOf`, `proofOf`, ...) and does not list these. `pathOf` is also not "innermost" as its comment says: it returns the first key in `subplans` whose list contains the plan.
- `apps/indusk-admin/src/lib/stamp.ts:8` — the same rejected alternative, on a smaller scale: one time format defined in the admin's `lib/` for the dashboard, promise page, plan history and timeline, where the ADR says the facts a person reads are computed once in the package.
- `apps/indusk-admin/src/lib/decisions.ts:100-172` — the routing of answers (question vs approve vs release vs say vs new session) and the reply prompt wording live in the admin; the ADR places what a plan waits on in `plans/waiting` and recording in `plans/history`, so routing is not a rejected alternative, but the prompt text (`replyPrompt`) is a second wording of "the decision it answers", defined once only in the admin and untested by A34.
