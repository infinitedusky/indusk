# Audit — brief-as-the-contract

## Does each row prove its promise's sentence, or something narrower?
- `apps/indusk-mcp/src/lib/promises/interface-files.ts:62-68` — `a-brief-lists-its-looks`, the promise that a plan changing an app's interface with no look listed is refused at approval. Rows A1–A3 prove it only for a `## Files Affected` cell that is one bare path. `filesAffectedOf` drops any first cell that contains whitespace, so `` `apps/indusk-admin/src/components/plan/` (new parts) `` and `` `a.tsx`, `b.tsx` `` are never read, and the plan is approved silently. Verified against the built `filesAffectedOf`. This plan's own approved impl uses both forms (approved impl, Files Affected rows 1–2).
- `apps/indusk-mcp/src/lib/promises/contract.ts:242,409` — the same promise. The look check runs only when the brief is in the contract shape. A brief with no `## Promises` heading (`legacy`), or a plan with no brief, is never held to Looks at approval, whatever its Files Affected names. A1 uses a contract-shaped brief, so it cannot see this. The same exemption applies at accept (`accept.ts:87`).
- `apps/indusk-mcp/src/__tests__/plans-accept-looks.test.ts:22` — the same promise. The second enforcement moment in ADR decision 2 (the accept-time check over the branch's real diff) is tested here, but no trajectory row names this file. Nothing in the trajectory proves the "changed more than it said" half.
- `apps/indusk-mcp/src/lib/looks/approve.ts:54-60,127` — `a-look-has-the-plan-that-owns-it`, "every approved look records the plan that made or last changed it". A4 proves this only for an approval made on a `plan/<x>` branch. An approval made in the project's own checkout, or on any other branch, records no plan, and nothing refuses it.
- `apps/indusk-admin/src/__tests__/plan-parts.test.tsx:142-149` — the same promise, second clause ("that plan's page shows its looks beside its promises"). A5 asserts only `data-approval="proposed"` on one row, never the owning plan. `readPlanParts` lists the looks the brief names (`parts.ts:176`), not the looks whose approval records this plan. A look the plan owns but no longer names is not shown, and a look owned by another plan is shown.
- `apps/indusk-mcp/src/__tests__/look-ownership.test.ts:50-99` — `a-changed-look-keeps-its-history`. A6 and A7 prove the append-only record. Nothing proves "a plan that redraws an existing look says so in its brief": a mockup redrawn under a brief that lists only other looks (or `None — reason`) passes approve, accept and the amendment gate. The accept check reads `sources` code paths, not `.indusk/mockups/`.
- `apps/indusk-mcp/src/lib/plans/approved-brief.ts:79-88` — `a-plan-is-approved-with-its-looks-approved`, "approved only after a person has approved each look its brief names". `looksToApprove` excludes **Must not break** looks, so a must-not-break look that reads proposed still passes approval. A8 and A24 test only makes/changes.
- `apps/indusk-mcp/src/lib/plans/approve.ts:42,107-125` — the same promise, and `a-new-component-ends-its-plan-with-a-story`. A workbench plan returns to `approveWorkbenchPlan` before `refuseUnapprovedLooks`, and `acceptPlan` returns for a workbench before `refuseUnlistedInterfaceChanges`/`refuseStoriesWaiting` (`accept.ts:59-67`). `reapprove.ts:85` also skips the looks gate for a workbench. A8, A24 and A25 run only normal-mode fixtures.
- `apps/indusk-mcp/src/lib/plans/approved-brief.ts:165` — `a-new-component-ends-its-plan-with-a-story`. A story is demanded only for a mockup that declares itself in `indusk-new-components`. A brief that names a new component whose mockup omits the declaration gets no story requirement at accept. Inferred, moderate confidence; A25's fixture always declares.
- `apps/indusk-mcp/src/__tests__/amendments.test.ts:151-157` — `a-change-to-what-was-agreed-needs-the-person`. A11 claims the amendment "is listed on the plan page as waiting". The test asserts only the `check-gates.js` stderr; no row renders the page's waiting list (`WaitingAmendments`).
- `apps/indusk-mcp/hooks/check-gates.js:71` — the same promise ("waits for a person's approval before the build goes on"). The existing `<!-- skip-gates -->` escape exits before the new amendment check under `gate_policy: ask` (this plan's own policy), so an amendment can be stepped past. A12 does not cover the escape.
- `apps/indusk-mcp/hooks/check-gates.js:298-301` — the same promise. The gate runs only while the impl frontmatter carries `approved_brief`, and an impl edit "waits for nobody" (A14). An agent that deletes `approved_brief` from the impl in one edit turns the amendment check off for every later checkoff, and `amendmentsOf` then returns `[]` (`amendments.ts:103-104`).
- `apps/indusk-mcp/src/lib/plans/amendments.ts:312` — the same promise. Withdrawing an owned promise from the registry (its file gone, or ownership moved) is skipped as "not a new sentence". A withdrawal made through the registry, with the brief left as it was, is no amendment. Expectation 1 counts withdrawals as the very thing this plan reduces.
- `apps/indusk-mcp/src/lib/plans/reapprove.ts:49` — the same promise, and the must-not-break `a-mockup-is-approved-by-a-person` ("an agent ... must never approve either"). A13 proves only that the HTTP route is browser-only. `indusk plans reapprove` from a terminal has no guard, and no hook refuses an agent's Bash call to it (grep of `apps/indusk-mcp/hooks/*.js`). The ADR accepted this as convention, but the promise sentences do not carry that caveat.
- `.indusk/promises/a-plan-builds-only-after-approval.md:10-12` — the changed promise `a-plan-builds-only-after-approval` gained "or that has an amendment waiting". No trajectory row names this promise, and its linked tests (`approval-gate.test.ts`, `planner-stops-at-the-plan.test.ts`) were not touched. It reads `enforced` while nothing linked to it proves the new clause.
- `apps/indusk-admin/src/__tests__/plan-parts.test.tsx:131-140` — `a-plan-page-shows-the-parts-of-its-brief`. A15 asserts three `data-part` attributes and the brief link. It never checks that each part shows names and states. "Updated as the agent writes them" rests on A16, which writes a mockup file directly in the system tier (`vitest.tiers.ts`, which never blocks landing), and on A17, a one-off manual check.
- `apps/indusk-mcp/src/__tests__/drafts.test.ts:90-102` — `a-conversation-that-is-not-kept-leaves-nothing-in-the-repository`, "with a brief when it makes promises or looks, with research alone when it does not". A21's "brief" case is `# promises\n`, which makes no promise, and it still becomes a plan with a brief. `startFromDraft` decides on whether `brief.md` exists (`drafts/start.ts:37`), not on what the brief makes.
- `apps/indusk-admin/src/app/api/drafts/[id]/accept/route.ts:30-34` — `a-plan-starts-as-a-conversation`, "named ... by the agent's proposal and the person's acceptance". A19 calls `startFromDraft` directly. The accept route has `adminOnly` but not the `fromTheBrowser` guard the reapprove route uses, and `plans start --from-draft` is open to the agent. Acceptance being the person's is a prompt instruction (`session/draft.ts:61`), not enforced.

## What does the diff change that no row touches?
- `apps/indusk-mcp/src/lib/plans/start.ts:228` — a draft brief that brings its own front matter is written verbatim. The type the person accepts or edits is not written to `workflow:`, and the agent's `status:` passes through. No row checks that the plan declares the accepted type.
- `apps/indusk-mcp/src/lib/drafts/start.ts:37-44` — a draft holding both `brief.md` and `research.md` keeps only the brief, then `rmSync` deletes the draft, research included. A spike whose draft has only a brief gets the brief text as `research.md` (line 38).
- `apps/indusk-mcp/src/lib/drafts/store.ts:165-172`, `apps/indusk-mcp/src/bin/commands/plans.ts:316` — ageing deletes drafts permanently. No trajectory row covers it (`drafts-age.test.ts` is unlisted).
- `apps/indusk-mcp/src/lib/plans/accept.ts:89-91` — the accept-time interface check reads `sources` from the plan's own branch (`pb.worktree`). A branch that edits `.indusk/mockups/<app>/screens.json` `sources` escapes its own check. Inferred, moderate.
- `apps/indusk-mcp/src/lib/plans/parts.ts:166-174` — when a mockup and a story share a name (the 4a pattern, where a new component's mockup and story are "the same name built"), the story overwrites the mockup in `drawn`. The plan page then loses the mockup's frame (`document: null`) and shows the story's approval instead. Same-named looks in two apps collide the same way.
- `apps/indusk-admin/src/components/LiveRefresh.tsx:39,74` — the liveness probe moved from the page itself to `/api/sessions`, so a plan page that fails to render while the API answers reads as live. The visible "last updated" text became `sr-only`.
- `apps/indusk-admin/src/app/api/drafts/[id]/discard/route.ts:21-25` — a draft can be discarded by any same-host request (`adminOnly` only). No row covers who may discard.
- `apps/indusk-mcp/src/lib/plans/approved-brief.ts:22-23` — the module header still says "A story is exempt". Lines 92-94 and ADR decision 4a say no name is exempt. A safety comment that contradicts the code it sits on (this repo's Known Gotcha).
- `apps/indusk-mcp/src/lib/plans/approved-brief.ts:57-58` — `approved_by` is whatever `git config user.name` says. An approval the agent runs records the person's name. No row covers who is recorded.

## Which rejected ADR alternative does the code quietly take?
- `apps/indusk-mcp/src/lib/promises/interface-files.ts:68` — "detecting that a plan touches the interface by reading its words" was rejected because "it misses by construction, and the miss is silent". The approval-time check parses the impl's own prose table and silently skips any cell it cannot read as one path. On those rows it has the silent-miss property the ADR rejected. The accept-time diff check (also silent for workbench plans, `accept.ts:59-67`) is the only loud backstop. Moderate confidence that this counts as the rejected alternative and not a weak form of the chosen one.
