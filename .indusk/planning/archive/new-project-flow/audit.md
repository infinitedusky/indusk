# Audit — new-project-flow

## Does each row prove its promise's sentence, or something narrower?
- `apps/indusk-mcp/src/__tests__/new-project-cli.test.ts:412` — **an-unkept-project-conversation-leaves-nothing-on-disk** (brief.md:60, "a conversation abandoned before acceptance creates no directory") is narrower in A18 (the trajectory row asserting an open conversation has created nothing outside its draft folder). A18 seeds the draft with `indusk new-project start` and never runs an agent. In a real conversation the agent is the only thing that can write outside the draft. It runs as a `planning` session that allows Bash, WebFetch and any tool given no path without asking (`apps/indusk-mcp/src/lib/session/manager.ts:84-90`, `apps/indusk-mcp/src/lib/session/permissions.ts:11-13,32-43`). The one thing holding it back is a line in the prompt (`apps/indusk-mcp/src/lib/new-project/prompt.ts:61`). A17 (discard removes the draft) holds for the discard path only. Confidence: high.
- `apps/indusk-mcp/src/__tests__/new-project-cli.test.ts:327` — **a-new-project-publishes-nothing-unasked** ("a remote repository is created only after the person confirms it") is narrower in A14 (creating with the remote confirmed makes one private repository and pushes). The page's checkbox starts from that agent-written value (`apps/indusk-admin/src/components/new-project/NewProjectProposal.tsx:225-230`), so an agent proposal with `github: true` arrives already ticked, and Create runs `gh` without the person doing anything. The accept route also re-reads `proposal.json` from disk (`apps/indusk-admin/src/app/api/new-projects/[id]/accept/route.ts:46`) after the save. Nothing stops a still-running agent from rewriting the file between the person's save and `stopDraftSession` (`accept/route.ts:39`). The "off until the person says so" component test (`NewProjectProposal.test.tsx:117`) passes only because its fixture has `github: false`. Confidence: high on the pre-ticked box; moderate on the race, which has not been seen.
- `apps/indusk-mcp/src/__tests__/new-project-cli.test.ts:319` — A13 (no confirm means no `gh` run and no remote) proves `gh` never ran. It does not prove "sends nothing off the machine": see the span finding under the next heading. Holds for `gh`.
- `apps/indusk-mcp/src/__tests__/new-project-cli.test.ts:194` — **a-new-project-is-made-by-the-agent** "installs InDusk" is narrower in A4 (accept makes the workbench, repo, worktrees folder, InDusk and a registry entry). ## What else would have to change for each promise to hold?
- `apps/indusk-mcp/src/lib/session/permissions.ts:32-43` and `apps/indusk-mcp/src/lib/session/manager.ts:84-90` (untouched) — **an-unkept-project-conversation-leaves-nothing-on-disk**, and with it **a-new-project-publishes-nothing-unasked** and **a-new-project-is-written-only-under-its-parent**. A project conversation's agent may run Bash, WebFetch or MCP tools without asking, so `git init`, `mkdir` outside the draft, `gh repo create` or a network call are all allowed. For the promises to hold rather than rest on the prompt, a project conversation needs its own decider: refuse path-less tools, or ask the person about them.
- `apps/indusk-mcp/src/lib/session/protocol.ts:70-71` (untouched) — `acceptEdits` applies to the project conversation unchanged. It is safe only together with the decider above.
- `apps/indusk-mcp/src/lib/eval/otel.ts:148-210` and `apps/indusk-admin/src/instrumentation.ts` (untouched) — **a-new-project-publishes-nothing-unasked** and expectations 1, 2 and 5. Either the admin registers a provider pinned to the local daemon for `new_project.create`, or the span can follow a provider registered for the recorder to `OTEL_EXPORTER_OTLP_ENDPOINT`. That endpoint may be off the machine (Dash0), which breaks "creating a project sends nothing off the machine". Today the span goes nowhere, or wherever another feature pointed the global provider.
- No admin settings page or route for the parent directory exists; `apps/indusk-admin/src/app/new/page.tsx` and `NewProjectStart.tsx` offer none — **a-new-project-is-made-by-the-agent** ("no command typed by the person") and expectation 1.
