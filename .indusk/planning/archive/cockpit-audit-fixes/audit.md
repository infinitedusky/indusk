# Audit — cockpit-audit-fixes

## Does each row prove its promise's sentence, or something narrower?
- `apps/indusk-mcp/src/lib/promises/proof.test.ts:502` — A5, the trajectory row asserting that the dashboard row and the promise page give the same held and broken days, uses a fixture with one source (production) only. The promise `the-thirty-days-say-only-what-was-seen` says the dashboard and the page "show the same days". But the dashboard's count (`standing.ts` `upheldRuns`) merges every source into one tally, while the page's day bars (`proof.ts:282`) are split per source. Say local saw a day upheld and production heard a break that same day: the tile shows a broken day, while local's bar shows the day green. Nothing in A5 compares the two surfaces with more than one source. The test also works out held/broke from the page's bars with its own `countsOf` helper, not with the page's code.
- `apps/indusk-mcp/src/lib/promises/standing.test.ts:333` — A4, the row asserting that a violation heard under a promise's earlier name counts "on the dashboard and on the promise page alike", only exercises `standingOf`, which is the dashboard's side. No row feeds `proofOf` (the page) a heard row or an upheld mark under an alias. The new alias loop for upheld marks at `proof.ts:274` has no test at all.
- `apps/indusk-mcp/src/lib/promises/standing.test.ts:301` — A1, the row asserting that a promise shows "held 3 · broke 1" on the dashboard, checks the `thirtyDays` object returned by `standingOf`, with the upheld times passed in directly (`as never`). It never checks the dashboard's rendered text, and it never exercises `upheldRuns`, the store read that supplies those times in production (`standing.ts:225`).
- `apps/indusk-mcp/src/__tests__/same-health-three-surfaces.test.ts:75` — A10, the row asserting that `indusk promises status`, the dashboard and a promise's page report the same state for each promise and source, gives `local` and `production` the identical `marks` object. A surface that read one source's marks for the other would still pass. The test also calls `reportRows` (`health.ts:225`) rather than the `indusk promises status` command. The brief says this row "runs `indusk promises status`".
- `apps/indusk-admin/src/lib/decisions.test.ts:310` — A7, the row asserting that an agent asking two questions has both shown and gets an answer to each, builds the `Waiting` value (with its `questions`) by hand. No row checks that `planWaiting` (`waiting.ts:129`) actually puts every question of a real ask into `questions`, so the card's input and the agent's question are never connected in one test. The CLAUDE.md line the plan added says "an answer that leaves one out is refused — guarded by A7", but neither A7 test sends an answer that leaves a question out (`decisions.ts:194`).
- `apps/indusk-mcp/src/lib/plans/waiting.test.ts` — A8 and A12 are rows asserting that approval is withheld while a session writes the impl and offered once its turn ends. They test `planWaiting` with a hand-set `writing` flag, and `SessionManager.isWriting` on its own (`manager.test.ts`). Nothing tests the link between the two, `decisions-reader.ts:41` (`writing: manager.isWriting(r.id)`). If that line were dropped, every live session would read as writing again and both rows would stay green.
- `apps/indusk-admin/src/app/p/[project]/promises/dashboard.test.tsx:328` and `apps/indusk-admin/src/app/p/[project]/cockpit-nav.test.tsx:462` — A13, the trajectory row asserting that when two Paths declare each other "the dashboard and the nav put X under the same Path", is not tested as worded. The dashboard test accepts either Path (`toContain`). The nav test asserts the plan is listed under both (twice in total). Neither test checks that the two surfaces agree. The docs edit says the plan "still appears under both", which contradicts the row's own sentence.

## What does the diff change that no row touches?
- `apps/indusk-admin/src/app/api/plans/[name]/decision/route.ts:82` — the route's new `choice: "answers"` parsing (it rejects non-object input and non-string values) has no test. The card tests check what the card posts, and the decisions tests call `answerDecision` directly, so the route between them is never exercised.
- `apps/indusk-admin/src/lib/decisions.ts:186` — for an ask of several questions, accept, alternative and reply now throw ("answer each one"). Before this plan they answered the first question. No row checks this refusal.
- `apps/indusk-admin/src/lib/decisions.ts:113` — for an `answers` choice, the history line records `waiting.decision`, which is only the first question's text, as the decision, and joins every answer into one string. No row says what a several-question answer looks like in `plan-history`.
- `apps/indusk-mcp/src/lib/promises/standing.ts:216` — `readStanding` now reads the store for every source, each with a 2 s timeout, on every dashboard load. `proofOf` reads it again for the page's days. No row covers a store that cannot be read. In that case `upheldRuns` drops held days silently, while the page records the source as `unread`.
- `apps/indusk-mcp/src/lib/session/manager.ts:184` — `turnOpen` clears only on a `result` event. If a turn ends some other way (interrupted, errored without a `result`) and the session stays alive, nothing stops it reading as writing forever, which hides approval. No row covers a turn that ends without a `result`.
- `apps/indusk-mcp/src/lib/plans/waiting.ts:138` — `beingWritten` does not filter by session `kind`, so a live build session with an open turn also withholds approval for a draft impl. No row pins either answer.
- `apps/indusk-admin/src/components/cockpit/DecisionCard.tsx:110` — when there are several questions, the card drops its title (`title={several ? undefined : …}`). No row or snapshot notices.

## What does the code do that the brief never promised?
- `apps/indusk-admin/src/components/cockpit/DecisionCard.tsx:52` — each question gets its own free-text box whose words replace the chosen option (A14, added after approval). The brief promises that each question is shown and answered, not that it can be answered in the person's own words. Its Looks line ("with its own answer") does not say so either.
- `apps/indusk-admin/src/lib/decisions.ts:186` — an ask of several questions now refuses accept, alternative and a single reply. That is a behaviour change to `decisions-wait-in-one-place`, a must-not-break promise, and the brief does not name it.
- `apps/indusk-mcp/src/lib/session/manager.ts:285` — `isWriting` reads "no session is still writing" as "no session has an open turn" (A12, added after approval). A live session idle after its turn no longer holds approval. The brief's Settled-by-default line ("one no running session is writing") is compatible with this, but the brief never states the turn-based reading.
- `apps/indusk-mcp/src/lib/promises/proof.ts:274` — the page now counts upheld marks recorded under a promise's earlier names as held. The brief promises alias handling only for violations ("a violation was heard that day (under its current or any earlier name)").
- `apps/indusk-mcp/src/lib/promises/standing.ts:127` — `StandingDeps.home` lets a caller choose where the record of heard violations is read from. The brief behind it says nothing about this; it serves tests.

## Which skip reason would you not accept?
- `.indusk/planning/cockpit-audit-fixes/impl.md` (approved, Build Phase 3 Context) — the gate is marked "(none — no convention changed …)", on the grounds that the Path rule is already in the planning rules. But Build Phase 3 created `apps/indusk-admin/src/lib/path-nesting.ts` as "the one place" the nav and the dashboard decide nesting, and that is a new single-reader convention of the same kind Build Phase 1 recorded in `promises/CLAUDE.md`.
