# Audit — ui-promises

## Does each row prove its promise's sentence, or something narrower?
- `.indusk/mockups/admin/approved.json:1` — `tokens-are-held-exactly` (and brief expectation 2, "the cockpit is held to its mockup"): A21 is the live-check row asserting that the cockpit end to end is held and that a token changed in the admin alone shows broken. It still reads `passing`, but nothing at the branch head is held. None of the eleven admin entries carries `declarationsHash`, and Build Phase 6 made `boundToNow` (`apps/indusk-mcp/src/lib/looks/approvals.ts:67`) require it. The foundation and mockup hashes still match, yet `indusk looks status admin` (run from source here) reads every mockup `proposed … nothing held`, `looks coverage admin` reports all 5 screens and 9 components uncovered, and `looks check admin` has nothing to check. A21 proves a state that later work in the same plan undid. Confidence: high (observed).
- `apps/indusk-admin/src/app/p/[project]/promises/page.tsx:74` — `tokens-are-held-exactly` / `every-part-of-the-ui-is-covered`: A36 is the row asserting that a state whose page does not report it is unchecked, never held. Only the dashboard page and the Looks page set `data-look-state`. The nav (2 states), promise (2) and plan (3) screens declared in `.indusk/mockups/admin/screens.json` never report one, so even after re-approval 7 of the cockpit's 11 screen states can never be held. A18–A20 are contract rows run against the fixture app, not the admin, so they do not show this.
- `apps/indusk-mcp/src/lib/looks/verdict.ts:229` — `tokens-are-held-exactly` says an easing or duration that differs from its approved value is broken. `isInitial` treats `ease`, `0ms`, weight `400`/`normal`, `transparent`, `0px`, `auto` and `normal` as "nobody set this" and never a break, and `verdict.test.ts:109` pins that. So an element whose approved easing token is swapped for `ease`, or whose approved weight token becomes `400`, reads held. A20 is the row asserting a differing duration or easing is broken; it tests 250ms against 200ms only.
- `apps/indusk-mcp/src/lib/looks/verdict.ts:56` — `tokens-are-held-exactly` says "every element … that claims a token". The check measures only the properties in `PROPERTY_KIND`: no `outline-*`, `line-height`, `letter-spacing`, `width`/`height`, `fill`/`stroke`, `animation-*` or `text-decoration-color`. `check.ts:81` walks only real elements in their resting state, so `::before`/`::after` and `:hover`/`:focus` styles are never read. A token changed in the app alone that only these use (the foundation has `--leading-*`, `--tracking-*`, `--size-*`, and the mockups animate `::after`) is not caught. A19 is the row asserting a token changed in the app alone makes every element using it broken; it proves this for the measured properties only.
- `apps/indusk-mcp/src/lib/looks/lint.ts:187` — `a-mockup-leaves-nothing-undefined` says no raw value "in the app". For `.tsx/.jsx/.ts` sources the lint runs only the class scan (`classFindings`). An inline style object such as `style={{ padding: "13px", color: "#f00" }}` is never linted. A6 is the row asserting the app's styles are held to the rule; it tests CSS, a stock class and an arbitrary class only. Nothing prevents a raw value from entering this way (none was seen in the admin today).
- `apps/indusk-mcp/src/lib/looks/lint-classes.ts:16` — same promise: the class scan knows colour, spacing, radius, text-size and shadow utilities. Tailwind utilities that compile to literal values rather than theme variables (`outline-2`, `outline-offset-1`, `border-2`, `duration-150`, `delay-*`) are neither scanned nor reset by the generated `@theme`. The admin uses `focus:outline-2 focus:outline-offset-1` (`apps/indusk-admin/src/components/ui/Button.tsx:29`) and `outline-2` in four other components. These pass `looks lint admin`, and the runtime check does not measure outline either.
- `apps/indusk-mcp/src/lib/looks/foundation.ts:180` — same promise: a stylesheet is exempt from the lint when its text merely *starts with* the generated header comment. Nothing checks that its body equals `generateCss(foundation)`. `looks-lint-rules.test.ts:65` (A31) pins that such a file produces no finding at all, so raw rules appended under the header pass the lint. Only the runtime check, on declared screens and measured properties, would see them.
- `apps/indusk-mcp/src/lib/looks/coverage.ts:48` — `every-part-of-the-ui-is-covered` says "every component it uses". Coverage only knows components whose source carries a literal `data-component`. In the admin, 7 source files carry one, while about 50 component files (`Scorecards.tsx`, `ProjectGrid.tsx`, `PromiseTimeline.tsx`, `PlanDetail.tsx`, …) carry none and can never be reported uncovered. A12 is the row asserting an unshown component is reported; it proves this only for marked components.
- `apps/indusk-mcp/src/lib/looks/coverage.ts:90` — same promise, "every screen the app has": screens come only from `screens.json`. The ADR's risk mitigation, deriving routes and reporting a route with no declared screen, is not implemented. The admin's project grid (`app/page.tsx`), project page, scorecards and research pages are not declared, so they are never reported uncovered. A10 is the row asserting a screen with no mockup is reported; it covers declared screens only.
- `apps/indusk-mcp/hooks/looks-approval-guard.js:34` — `a-mockup-is-approved-by-a-person` says an agent can "never approve" a mockup. The hook is registered on `Edit|Write` and `Bash` (`apps/indusk-mcp/src/lib/hook-command.ts:48`). An agent driving a browser through the Playwright MCP, which is on this user's global keep-list, can open `indusk ui` and click Approve. That is a real browser request with `Sec-Fetch-Site: same-origin`, so `route.ts:37` accepts it, and no hook sees the MCP tool. The ADR's stated residual covers scripts that build the path or forge headers, not this ordinary agent tool. Separately, `MultiEdit` is in `WRITE_TOOLS` but not in the `Edit|Write` matcher, so the hook is never invoked for it. A28 and A29, the rows asserting Bash writes and route calls are refused, prove "an agent's Write/Edit/Bash is refused", which is narrower than "never".
- `apps/indusk-admin/src/components/looks/Looks.tsx:219` — `mockups-render-in-the-cockpit` says a mockup opens "at each reference device". The frame takes the device's width and height, but the declared pixel ratio (`@2`, `@3`) cannot be applied to an iframe. A15, the row asserting the frame matches the device's width and height, proves exactly that and no more. Low consequence.
- `apps/indusk-mcp/src/lib/promises/look-standing.ts:195` — `a-look-reports-like-any-promise` / brief expectation 2 ("a drift is caught without a person looking"): no row and no code runs the look check unprompted (see question 6). A22–A24, the rows asserting a run is recorded, counted, and shown in the editor, prove that a run someone triggers is reported. They do not prove that a drift is caught when nobody runs `indusk looks check`.

## What does the diff change that no row touches?
- `apps/indusk-mcp/src/lib/looks/check.ts:261` — a page that answers non-OK throws `LooksCheckError` out of `checkApp` mid-loop. `looksCheck` (`apps/indusk-mcp/src/bin/commands/looks.ts:126-131`) then never reaches `reportLooks`, so spans for screens already judged in that run, broken ones included, are dropped. The dashboard keeps showing their previous run, which may be held. No row covers a partial run.
- `apps/indusk-mcp/src/bin/commands/looks.ts:128` — an unchecked look (page did not report its state, or the wrong scheme) is printed but emits no span. `newestRunSince` (`look-standing.ts:79`) then keeps returning the last held run since approval. A look the check could no longer judge goes on reading `held` on the dashboard and in the editor. A36, the row asserting an unreported state is unchecked and never held, asserts this of the check's own output, not of the standing reader.
- `apps/indusk-mcp/src/lib/promises/look-standing.ts:195` — runs are read from a 7-day window. A broken look not re-checked for a week silently becomes `not checked` and drops out of the nav's broken count with nothing mended. Runs are also read only from the local daemon (`readLookRuns`, line 246), never a production source. No row pins either.
- `apps/indusk-mcp/src/lib/looks/foundation.ts:180` — the generated-file exemption is judged by its first line only (detail under question 1). No row asserts that a header-prefixed file with extra raw rules is refused; A31 pins the opposite.
