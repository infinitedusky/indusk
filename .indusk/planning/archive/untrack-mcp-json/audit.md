## What does the code do that the brief never promised?
- `apps/indusk-mcp/src/lib/mcp-config.ts:95-96` — A telemetry daemon start/restart now creates a `.mcp.json` (with an `indusk` entry) in every registered project directory that exists and has none. Previously it created one holding only `jaeger`. The brief promises update-side creation and never overwriting, not a daemon-side file creation; the brief's own "Not promised" lists jaeger registration from `update`, but not this inverse side effect.
- `apps/indusk-mcp/src/lib/worktree/plan-worktree-commands.ts:189` — New plan worktrees receive a copy of the trunk's `.mcp.json` including its `jaeger` URL with the trunk's port and any hand-added servers (T8 asserts `mine` is carried). The brief says nothing about worktrees; tokens in headers (the `.gitignore` comment says the file "contains auth tokens") are duplicated into another directory.
- `apps/indusk-mcp/src/lib/mcp-config.ts:36-43` — `ensureMcpJson` shells out to `which`/`where indusk` and chooses between `indusk serve` and `npx --yes @infinitedusky/indusk-mcp serve` by the machine's PATH; the brief only says "names the `indusk` server".
- `apps/indusk-mcp/src/lib/mcp-config.ts:24-30` — `readMcpJson` returns `{ mcpServers: {} }` on a parse error, so `upsertJaegerEntry` on a present-but-corrupt file silently replaces it with only `jaeger` (pre-existing behavior moved, now one line after an `ensureMcpJson` that reports "present"). This contradicts the promise's "never overwrites a `.mcp.json` that exists" for the daemon path, though the promise is worded about "one `indusk` command".
- Deleting `.mcp.json` from the index means every existing clone loses the file on pull (the changelog says so); the brief does not promise any migration, only the docs note.

## Which skip reason would you not accept?
- `.indusk/planning/untrack-mcp-json/impl.md:11` — `cleanup: skipped` with `cleanup_reason`. Mostly holds (the file counts and the 103-line module description check out), but the reason says the new module has "three consumers each import it once" and the only repetition is the PATH probe; it does not mention that `hasGlobalIndusk` (`mcp-config.ts:36`) and `init.ts:684` now disagree on mechanism (`spawnSync which` vs `run("which indusk") || run("where indusk")`) and on what is written (`init` goes through `claude mcp add`; `ensureMcpJson` hand-writes the JSON shape). Two writers of the same file's `indusk` entry is exactly what a cross-file cleanup should name; I would accept the skip only with that noted as deliberate.
- T4 (retired in Test Phase 1) — reason holds: `grep add_command apps/indusk-mcp/extensions/*/manifest.json` returns nothing, so no built-in extension declares a server for `update` to add (the `update.ts:670` branch exists but has no built-in input). Accepted.
