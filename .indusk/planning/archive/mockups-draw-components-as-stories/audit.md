# Audit — mockups-draw-components-as-stories

They prove the generator's output, not that anything draws that way. The drawing claim rests entirely on A4, the composition browser check.
- `apps/indusk-mcp/src/lib/looks/component-styles.test.ts:231` — A3 (unit row: the resets reach only components and the page around them draws as before) checks that every selector *contains* the scope string, and that a few selectors are absent. Nothing renders a mockup's own page and compares it before and after, so "the page around them draws as before" is inferred from the selector shape, not observed.
- `apps/indusk-admin/src/__tests__/composition.contract.test.ts:400` — A4 (contract row: every component each admin mockup places draws with its story's computed values) draws each mockup at one wide viewport (`WIDE`). The promise says "at each reference device". Nothing checks that a component in a mockup draws as its story does at the phone or tablet widths.

In `home.default` every project card is given its own project name, so the card and its text boxes are never size-checked. The research's "~3 px narrower text boxes" finding sits exactly in that blind spot. A4 proves computed styles match, which is narrower than "drawn as its own story draws it".
- `apps/indusk-admin/src/__tests__/composition.contract.test.ts:213` — in A4, `logical` treats `start` and `left` (and `end` and `right`) as equal for `text-align`, and is only correct in left-to-right pages. The comment admits that. It is narrower than the promise for any right-to-left mockup.
- `apps/indusk-admin/src/app/p/[project]/looks/looks-components.contract.test.ts:68` — A5 (contract row: every admin story fits its frame at each device, a long message wraps) now runs against `startNextBuilt`, a production `next build`, not the `indusk ui` daemon a person opens. That is a reasonable stand-in for "nothing to run beside the cockpit", but it is still a stand-in.
- `apps/indusk-mcp/src/lib/looks/approvals.test.ts:434` — T1 and T3 (unit rows added after falsification: an approval binds the app's element rules, and a look last approved under other rules is held to nothing) are tagged `promise: mockups-render-in-the-cockpit`, but they prove something that promise's sentence does not say. The sentence is about how looks draw, not about when an approval lapses. They cover no clause of the promise as worded.
- `apps/indusk-mcp/src/lib/looks/compose.test.ts:14` — A6 (unit row for `a-mockup-composes-approved-components`: a mockup shows a component only by naming it, and one it draws itself is refused unless declared new) points at `compose.test.ts`, which has no refusal assertion. ## What does the diff change that no row touches?
- `apps/indusk-mcp/src/lib/looks/component-styles.test.ts:235` — `scoped()` puts the scope *before* a pseudo-element (`:where(...)::before`). A3 only checks that the scope string appears somewhere in each selector. If the scope ended up after `::before`, the selector would be invalid and Chromium would drop the whole `*, ::before…` box-sizing/margin rule. No unit row would notice; only A4 might, indirectly.
- `apps/indusk-mcp/src/lib/looks/overview.ts:134` — `storyDocument` (the cockpit's own story frame) now loads `_reset.css`. A4 compares mockups against the stories served by Storybook, and `overview.test.ts:37` passes `reset: ""`. No row checks that a cockpit story frame draws with the reset, or in what order.
- `apps/indusk-admin/src/components/looks/useFittedFrame.ts:45` — height is still `r.bottom + r.top`, so a component aligned to the bottom or centred vertically would grow the frame, the same bug width had. No row exercises the vertical case.
- `apps/indusk-admin/src/components/looks/useFittedFrame.ts:76` — the auto-margin detection relies on `computedStyleMap`, which Firefox lacks. There it falls back to the used margin, so a centred story would keep the frame's own width. T2 and A5 run only in Chromium.
- `apps/indusk-mcp/src/bin/commands/looks.ts:67` — the `looks status` line's wording changed to "…declarations or element rules — nothing held". T3 tests `boundToNow` directly. No row reads the status line itself.
- `apps/indusk-admin/src/components/ui/ProjectCard.tsx:16` — the card's API changed: `extra` was removed, `shape`/`inProgress` were added, and `lastSeen` is now required. `content-start` was also added at line 40. No trajectory row covers the home page still showing shape, progress and last-seen. Only the existing `ProjectGrid*.test.tsx` would, and they are not in the trajectory.
- `apps/indusk-mcp/src/lib/looks/mockups.ts:431` — `readStyles` now leaves `_reset.css` out of the component sheets. Nothing asserts that `_reset` is not read as a component named `_reset`.
- `apps/indusk-mcp/src/lib/looks/approvals.ts:182` — an entry with a non-string `baseRulesHash` is now rejected by `isEntry`/`isStoryEntry`, and an entry without one binds nothing. T1 covers absence, but no row covers a malformed value.
