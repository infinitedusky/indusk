# Audit — nav-row-legible

## Does each row prove its promise's sentence, or something narrower?

- apps/indusk-admin/src/components/PlanList.worktree.test.tsx:112 — Promise `a-nav-row-keeps-its-parts-apart` (title on one line, stage on the next, mark beside the stage and apart). A1 proves this only for a short stage with no extra badges and a 280 px nav. The stage text is found by `span.truncate` index `[1]`, so the "8 px" is measured from the stage's text range, not from the stage plus its `malformed`, `HoldingBadge` and `RedDot` siblings. The fixture plan has none of them. A long stage, or a stage with a holding badge, is never drawn with a mark beside it.
- apps/indusk-admin/src/components/PlanList.worktree.test.tsx:156 — Same promise, "widens in place". A3 checks that the name appears, that the mark's centre stays within the stage line, and that the row height is unchanged. It never checks that the stage text keeps its position or width, or that the mark's left edge stays put. In `PlanRow.tsx:77-80` the stage span and the mark are siblings in a flex line and both can shrink. An opened mark can therefore squeeze the stage to an ellipsis or move it, and no row would go red. "In place" is proved as "on the same line".
- apps/indusk-admin/src/components/PlanList.worktree.test.tsx:156 — "Hovering or clicking ... widens". A3 and A4 use `userEvent.hover` and `click` in desktop Chromium. The mark's open state on touch is untested: `WorktreeMark.tsx:36-41` sets `hovered` on `pointerenter` and clears it on click. The brief's own phone promise makes touch the likely input.
- apps/indusk-admin/src/components/PlanList.worktree.test.tsx:192 — Same promise, "without opening the plan". A2 clicks the mark with `userEvent.click`, with a `preventDefault` listener on the link. It does not click the opened mark's name (a wider hit area) and does not press Enter or Space while the mark is focused to see whether the link fires. A4 toggles by keyboard but does not count link clicks.
- apps/indusk-admin/src/components/PlanList.worktree.test.tsx:239 — `the-nav-fits-a-phone`. A6 uses the `collapsed` prop at a 1280 px viewport. No phone-width viewport is drawn. The check `if (mark) expect(mark.checkVisibility())` and `if (wt)` are conditionals that pass vacuously if the mark is absent. That is fine for "hidden", but the same code would pass if the mark were never rendered even in the expanded nav. A1 covers that only indirectly. The impl's verification names `cockpit-phone.test.tsx` among the related tests, but it is not a trajectory row.
- apps/indusk-admin/src/components/PlanList.worktree.test.tsx:1 — `paths-keep-their-order` is a "must not break" promise in the brief and no trajectory row names it in `For`. The row is also rebuilt for numbered rows (`PlanRow.tsx:45-47,59-60`, where the number cell sits in the container, outside the link). No test draws a numbered row (`number` given) that has a worktree. Order and nesting are protected only by the unrelated existing `PlanList.test.tsx` and `cockpit-nav.test.tsx`, whose fixtures have no worktree.
- apps/indusk-admin/src/components/PlanList.worktree.test.tsx:132 — `every-plan-is-one-click-away` says the title is one click to its page and the mark is a separate control beside the link. A2 proves the click lands on the link at the centre of the title, badge and stage. It does not show the click reaches the *plan page* (the link's handler is replaced by `preventDefault`). It does not cover the number cell, which `PlanRow.tsx:60` places outside the link in this form (the brief's note admits `cockpit-nav.test.tsx` reads the badge inside `a[data-plan-name]`).
- apps/indusk-admin/src/components/PlanList.worktree.test.tsx:214 — A9 checks `closest("[title]")` at the title's centre. It passes because the link has `title={name}` (`PlanRow.tsx:66`), so it cannot tell a tooltip on the link from the same text on any ancestor. It is a fair proxy for the browser's tooltip, not the tooltip itself.
- apps/indusk-admin/src/components/PlanList.worktree.test.tsx:220 — A10 asserts that an outline exists on the link's `::after` and that its box spans the row. It does not compare the ring with the worktree-less row's ring (width, colour, offset, radius). The test title says "as the row without a worktree does"; the assertion proves only "some outline on the overlay".
- apps/indusk-admin/src/components/PlanList.worktree.test.tsx:239 — A8 (the contract guard) lives in `http-plan-worktrees.test.ts`, which this plan changed only by a comment. The diff does not show it was re-run after the Build Phase 3 changes, and the system tier never blocks landing, so A8's "passing" is unverified from the files.

## What does the diff change that no row touches?

- apps/indusk-admin/src/app/globals.css:201 — A new utility `.cols-fill`, a one-column grid. No row names it; it is used only by the container row.
- apps/indusk-admin/src/app/globals.css:360-379 — The collapsed-nav rules (`.nav-row-text { display: contents }` and `.nav-row-link { position: absolute; inset: 0 }`) are covered only through A6's badge click and height. The other consequence is untested: in a collapsed nav the link no longer has the title text as its content, and its accessible name comes from `title`/`aria-label`-less empty content. A collapsed worktree row's link has no visible text (the title span is `nav-hide`), so a screen reader may announce an unlabelled link. The `title` attribute is the only name. The non-worktree collapsed row has the same shape, so this may be inherited, but the plan did not check it.
- apps/indusk-admin/src/components/ui/PlanRow.tsx:63-76 — The link now carries `title={name}` over the whole row. Hovering the badge, number or stage in a worktree row now shows the plan's full name. In the worktree-less row only the title text carries `title` (`PlanRow.tsx:96`). No row asserts this difference, and A9 asserts only the title.
- apps/indusk-admin/src/components/ui/PlanRow.tsx:70-74 — The title span still carries a redundant `title={name}` under the link's own. The impl's Build Phase 3 says "the span's can stay". It is dead markup the overlay can never let the pointer reach.
- apps/indusk-admin/src/components/ui/PlanRow.tsx:57 — The empty-slot rule (`worktree != null && worktree !== false`) is covered only by A11 for `null` and `false`. The plan added a new public prop contract (`ReactNode`, falsy meaning absent) with no row for `""` or `0`, which are valid `ReactNode` values and would select the container form.
- apps/indusk-admin/src/components/Worktrees.tsx:26 — The page's wrapper changed from the `Tag` (a visible element) to `<span className="contents">`. A flex child that is `display: contents` does not take `min-w-0`/flex sizing; the row relies on the mark's own `min-w-0 shrink`. This is not tested at a narrow width.
- .indusk/mockups/admin/components.json — The regenerated catalog, three new `.html` snapshots and two stylesheets, and `plan-row.css` growing by 62 lines. The plan's text says the plan-row's existing states' snapshot hashes must not move. No row asserts it, and the diff here does not show it. The impl states that the nav looks read proposed again and are a person's to re-approve; no file shows that happened.
- apps/docs/src/changelog.md — A changelog line, and two docs pages. No row, correctly, but the changelog edit was written in Build Phase 2 and the Build Phase 3 changes (tooltip over the whole row, focus ring) were skipped from docs.

## What does the code do that the brief never promised?

- apps/indusk-admin/src/components/ui/PlanRow.tsx:63-67 — The whole row's tooltip is the plan's name, including over the badge, stage and holding badge. The brief promised nothing about tooltips; the worktree-less row does not do this.
- apps/indusk-admin/src/app/globals.css:372-379 — A custom focus style: the link's own outline is removed and an outline is drawn on its `::after`. The brief says nothing about focus rings. It changes a keyboard-visible style for every worktree row, and that ring's width and colour come from tokens the plan chose.
- apps/indusk-admin/src/components/ui/WorktreeMark.tsx:25-41 — The click handler clears `hovered` (`setHovered(false)`) and `pinned` toggles independently. A pointer resting on a pinned-then-unpinned mark closes it at once, which the brief's "hovering or clicking" does not specify. A user who clicks to close while still hovering sees it close under their pointer and not reopen until the pointer leaves and returns.
- apps/indusk-admin/src/components/ui/WorktreeMark.tsx:10-11 — A public `open` prop "for a story" sets initial pinned state. It exists for the story, not for a promise.
- apps/indusk-admin/src/components/ui/WorktreeMark.tsx:34 — `aria-label="Worktree <name>"` overrides the button's content, so a screen reader never hears the opened state's visible name as content; it hears the label whether open or closed. That is the mechanism for A8, not a promise.
- apps/indusk-admin/src/components/Worktrees.tsx:9-10 — The docblock and `apps/indusk-admin/CLAUDE.md` both say "the plan header keeps its tag". On `main` the plan page never rendered `WorktreeChip` (the only use was `PlanList.tsx:349`), and `app/p/[project]/plan/[name]/page.tsx` renders no ⎇ tag now. The statement in the docs and in the context file is false: there is no plan-header tag to keep.
