## Which rejected ADR alternative does the code quietly take?
- `apps/indusk-admin/src/lib/build-host.ts:122` — "No cap", which the ADR rejected because "a person pressing Build on many plans, or a loop starting sessions, would run without bound". `startBuild` admits a build by checking `held.size`, which counts only the sessions alive at that moment. A build that is between steps, or has not yet launched its first step, holds no slot. So pressing Build on N plans in quick succession admits all N, and every step after that skips the cap (`manager.ts:153`, `inBuild`). `startRelease` (`build-host.ts:154`) never checks the cap at all. For builds and releases the bound is therefore the number of plans, not `sessions.max`. The docs (`apps/docs/src/reference/admin-ui/overview.md:117`) say a build "holds its place under the cap from its first step to its last", but nothing reserves that place. (high)
