# Audit — plans-are-promises

The brief has one promise, `a-plan-holds-the-promises-it-lands`, two existing promises it must not break, and five prose clauses under the first. Findings are about what the passing rows prove, not whether the code runs.

## Does each row prove its promise's sentence, or something narrower?
- `apps/indusk-mcp/src/lib/promises/confirm.ts:33` — "done when every clause of every promise it holds is proved" is proved only as "each split/limit clause has a row whose state cell says passing and whose Test cell names a file that exists and carries the promise token". `carriesToken` is called with the promise, never the clause, so a test file named by a clause row need not mention the clause. A9 (closing refuses an unproved clause) and A16 (the live check) prove the bookkeeping of rows, not that anything tests the clause. State `passing` is hand-edited text; nothing runs the test.
- `apps/indusk-mcp/src/lib/promises/clause-rules.ts:69` — The clause `each promise has its clause plan` says the plan names each clause's signal AND the tests tied to it. `clausePlanRefusals` checks a `- Signal:` line is non-empty and nothing else. The tests half of the clause is not read by anything, so A5, A6 and A8 prove "a heading and a non-empty signal line exist", narrower than the clause. "Written before the ADR" is also not enforced by anything (the check runs only if `test-plan.md` exists, and has no ordering rule).
- `apps/indusk-mcp/src/lib/promises/rows.ts:140` — The clause `a promise can rest on another` says a resting clause's "health is that promise's health". The code only checks the target is `enforced` (or proved by the same close) at the moment of closing; after that nothing links the two. A11, A17 and A19 prove the close-time gate, not the health relation the brief words.
- `apps/indusk-mcp/src/lib/promises/rows.ts:197` — A promise made only of resting clauses cannot close: `clauseRefusal` returns null, then the old row check fires ("no test row names it") because no row names the promise. A11 says a resting clause is proved "with no row of its own"; A17 only covers a promise that also has non-resting clauses, so this case is unpinned.
- `apps/indusk-mcp/src/__tests__/promise-clauses.test.ts:305` — A13 ("a plan that has not opted in validates, passes the contract check and closes exactly as before") is asserted only through the contract check. The "closes as before" half rests on the unchanged pre-existing confirm tests, not on any row. Also the row's `For` names `a-plan-holds-the-promises-it-lands`, not the brief's existing promise `a-closed-plan-kept-its-promises`, so that must-not-break promise has no row naming it.
- `apps/indusk-mcp/src/__tests__/row-purpose.test.ts:165` — A15 says a clause row counts as naming its promise in "the promise's proof, its incidents and its standing". The test only checks `rowsNamingIn`. `route.ts:67` (incidents) reads `purpose.promises` and so works by construction, but no row exercises incidents or standing. The must-not-break promise `every-test-says-what-it-is-for` is named by this row and the clause token is read by it.
- `apps/indusk-mcp/src/lib/promises/rows.ts:124` — The clause `a promise is made of clauses` defines a split as "a point reached within its budget" and a limit as "a bound that always holds". The code treats `split` and `limit` identically (both just need a passing row). No row distinguishes them, so the kinds are labels, not behaviour.
- `.indusk/promises/a-plan-holds-the-promises-it-lands.md:1` — The plan's own promise is registered with no clauses and the brief does not opt in, so none of the five prose clauses is a clause row. A1–A19 are all attached to the single sentence, never to a clause. The plan does not eat its own definition of done.
- `.indusk/planning/plans-are-promises/impl.md:72` — A16 (the "whole story", Level live check) is a row with Test `manual: indusk promises contract demo && …`. `parseOptionalTestRefs` makes that one string a test "file" (no comma in it), and `carriesToken` would report it `missing`. So the row that is supposed to prove the promise end to end cannot satisfy `confirm` for this plan's own promise.

## What does the diff change that no row touches?
- `apps/indusk-mcp/src/lib/build/review.ts:171` — `reviewPromises` now passes the registry to `rowProofs`, so the build review's per-promise proof changes for promises with clauses. No row covers the build review (the cleanup gate and confirm are covered by A9, A17).
- `apps/indusk-mcp/src/tools/promise-tools.ts:70` — the MCP `declare_promise` tool gains a `clauses` argument. No row exercises it; `promises-declare.test.ts` goes through the CLI only.
- `apps/indusk-mcp/src/lib/release/route.ts:227` and `apps/indusk-mcp/src/lib/promises/proof.ts:117` — both lookups were rewritten onto `findPromise` (and `live` now filters retired promises before the lookup). A20 pins `findPromise` alone; nothing notices if `live` or `proofOf` stops resolving aliases or retired promises correctly.
- `apps/indusk-mcp/src/lib/promises/brief-contract.ts:236` — frontmatter is now parsed with a regex for `clauses: required` (quoted or not, trailing spaces). The accepted forms (`clauses: "required"`, `clauses: required # note`) are not pinned; a comment after the value silently turns the opt-in off.
- `apps/indusk-mcp/src/lib/promises/brief-contract.ts:311` — for a brief that has not opted in, a sub-bullet starting with a bold backticked name now marks its line as read and is silently parsed as a clause (errors dropped). A18 covers indented bullets as promises, not this.
- `apps/indusk-mcp/src/lib/promises/registry.ts:277` — `clausesProblem` runs for every promise file in the registry on every read. A malformed `clauses` list now makes the whole registry read report a problem; only the self-rest and unknown-kind cases have rows (A19, A3).
- `apps/indusk-mcp/src/lib/promises/contract.ts:307` — the row-clause check runs for every plan, opted in or not. A7 covers a missing clause; a row naming `clause: p/c` where `p` has no `clauses` at all is refused with "its clauses are none", which no row asserts.
- `apps/indusk-mcp/templates/workflows/feature.md:1`, `apps/indusk-mcp/src/lib/promises/rows.ts:33` — `NamingRow` gains a `clauses` field read only by `clauseRefusal`; `rowsNamingIn` callers elsewhere (`route.ts`, `check.ts`) now carry data nobody asserts they ignore.

## What does the code do that the brief never promised?
- `apps/indusk-mcp/src/lib/promises/rows.ts:127` — a resting clause is also satisfied by a sibling promise of the same plan being proved in the same close, plus cycle detection naming the chain. The brief says a clause can be another promise "of the part beneath it" and its health is that promise's health; nothing says siblings count or that cycles are refused. The ADR's close rule (D7) said `enforced` only.
- `apps/indusk-mcp/src/lib/promises/check.ts:295` — `indusk promises check` now fails the whole registry when any promise has a resting clause whose target is not held. Retiring or deleting a promise that another promise rests on turns the repo-wide check red. No promise or scope line covers a registry-wide invariant.
- `apps/indusk-mcp/src/lib/promises/registry.ts:291` — a promise file may not rest on itself (or an alias of itself); the registry reader refuses. Behind no promise or expectation.
- `apps/indusk-mcp/src/lib/promises/brief-contract.ts:207` — the brief reader changes how a nested bullet is read (an indented bullet under a promise becomes its clause) when opted in. The brief names clauses, not a Markdown nesting rule; the brief's own scope line "clauses as sub-entries" is the nearest cover.
- `apps/indusk-mcp/src/lib/promises/brief-contract.ts:108` — `parseClauseSpec` accepts a `:` or `.` after the kind, any non-space name, and trims a `**`name`**` wrapper. A lenient grammar the brief does not give.
- `apps/indusk-mcp/src/lib/promises/write.ts:164` — declaring a promise refuses a clause given twice; nothing in the brief says duplicates are refused (the registry reader does too, at registry.ts:679).
- `apps/indusk-mcp/src/lib/promises/rows.ts:827` — the refusal for a failing clause row lists every row naming the clause that is not passing; a second row can block a clause a first row proves. Not in the brief.
- `apps/indusk-mcp/src/lib/promises/registry.ts:716` — a new exported `findPromise` helper and five-site refactor; cleanup work, not promised.

## Which rejected ADR alternative does the code quietly take?
- `apps/indusk-mcp/src/lib/promises/write.ts:287` — the ADR rejects "Clauses only in the brief" because the promise outlives the plan. The registry does hold the clauses, but `replace_promise` goes through `declarePromise` without `clauses` and the plan's Out of Scope leaves `change`/`replace` without clauses, so after declaration the registry copy is frozen and the brief is the only editable place. Everything else (clause plan in one file, token in `For`, opt-in) matches the ADR's chosen side.

## Which skip reason would you not accept?
- `.indusk/planning/plans-are-promises/impl.md:142` — "A16 deferred to Build Phase 3 … a live check run once". Deferral itself holds (nothing to run earlier), but the record deviates: the phase item says `indusk init --local`; the run used `--no-index` because `--local` "fails at git add" under `plans start`, "a defect outside this plan". That defect is not logged anywhere I can see, and the check never ran under the setup the item named.
- `.indusk/planning/plans-are-promises/impl.md:72` — A16's Test cell is `manual: …` and the row is `passing`. A manual check recorded as a passing row with a pseudo test file does not hold as the proof for this plan's own promise (see question 1); I would not accept it without a code-bearing test.
- `.indusk/planning/plans-are-promises/impl.md:72` (the A14 row's `For`) — reason "a regression guard over the two copies of the row-purpose reader … must not drift". The ADR itself names this drift as the plan's main risk and A7's "refused when the impl is saved" depends on the hook reading the clause; the row serves the promise's clause-row behaviour and `every-test-says-what-it-is-for`, so "not for a promise" is too weak.
- `.indusk/planning/plans-are-promises/impl.md:456` — the Build Phase 5 Shape step reports "The Shape collector did not load under `tsx` here, so the review was read by hand", and the Shape items in Phases 1–3 say "nothing to change" with no file named. A review that did not run should not close as done.
- `.indusk/planning/plans-are-promises/impl.md:443` — "The clause grammar stays beside the brief reader" and the fixtures-stay review items are reasoned and acceptable; the `(none needed)` and `*_skipped` pairs do not appear anywhere in the impl (checked by grep), so nothing else to reject.

## What else would have to change for each promise to hold?
- `apps/indusk-mcp/src/lib/promises/confirm.ts:33` — `carriesToken` (untouched) looks only for `promise: <name>` in a clause's test file; for a clause to be proved by its test, the token check would need `clause: p/c` carried too.
- `apps/indusk-mcp/src/bin/cli.ts:1350` — the `change` and `replace` commands (and `apps/indusk-mcp/src/lib/promises/write.ts` `replacePromise`/`changePromise`) take no `--clause`; a replacement of a promise under an opted-in brief cannot be declared with its clauses, and a clause cannot be edited after declaration, so brief and registry can only be reconciled by withdrawing the promise.
- `apps/indusk-mcp/src/lib/promises/health.ts` and `apps/indusk-mcp/src/lib/promises/proof.ts` — untouched; "a clause can be another promise, and its health is that promise's health" would need health and standing to read the `rests-on` clauses of a promise. They read none.
- `apps/indusk-mcp/src/lib/promises/display.ts:279` and `apps/indusk-admin/` — untouched; the plan page and `STARTING_DOCS` still treat `test-plan.md` as an ordinary document, so "the plan page shows each promise's clause plan where it showed the test plan" (brief, Looks) is true only by the document's text. The ADR accepts this, but nothing renders the clause plan as such.
- `.indusk/promises/a-plan-holds-the-promises-it-lands.md:1` and `.indusk/planning/plans-are-promises/brief.md:1` — untouched; brief and registry file hold the five clauses as prose and no clauses, so this plan does not itself hold under `clauses: required`.
- `apps/indusk-mcp/src/lib/promises/proof.ts` and the `promises status` readers — "is done when every clause … is proved" depends on `mark-first` for proof by signal, which the brief assigns to another plan; until then "proved" means a row marked passing.
- `apps/indusk-mcp/src/lib/promises/contract.ts:434` — "written before the ADR" would need an ordering rule between `test-plan.md` and `adr.md` in the plan-folder checks (`plan-folder.ts` untouched); none exists.
