# Mockups draw components as their stories do — Research

## Question

Why does a component drawn in a composed mockup differ from its story, and why
does `message.you` overflow its frame?

## Background

The 1.71.0 release's slow tests raised seven incidents on 2026-10-16. Five
were stale tests (fixed and landed 2026-10-17). The composition check (A30 in
storybook-components, `apps/indusk-admin/src/__tests__/composition.contract.test.ts`)
and the story-frame check (A18, `looks-components.contract.test.ts`) were also
stale — matching components by top-level position, and outrunning `next dev`
with 113 stories — and once fixed on `plan/storybook-components` they reported
real differences.

## Findings

### Composed mockups lack Tailwind's base reset

A component's mockup stylesheet (`.indusk/mockups/admin/components/<name>.css`)
is generated by `indusk looks stories` from the app's compiled CSS
(`apps/indusk-mcp/src/lib/looks/component-styles.ts`). It carries the classes
the component uses, not Tailwind's preflight. A story has the preflight. So any
component relying on a preflight reset draws differently in a mockup:

- `project-card` is an `<a>`: preflight's `a { color: inherit }` is absent, so
  in `home.default` it draws `rgb(0,0,238)` (browser link blue), heading too.
- `prompt-box`'s `<textarea>`: preflight's `font: inherit` is absent, so it
  draws the browser's monospace at 13.33 px instead of IBM Plex Sans 15 px.

### `project-card` spacing in `home.default`

`gap` reads 16 px in the mockup, 4 px in the story, and the card's text boxes
are about 3 px wider. Likely the mockup's own CSS overriding a component class
(a mockup's unlayered rules beat layered ones — the reason A30 exists); not yet
confirmed.

### `message.you` is not fitted to its frame

The story's component draws 7,796 px wide in a 4,164 px frame. On 2026-10-14
e5915cbc4 removed Message's arbitrary `overflow-wrap` class because the looks
lint refused it; long unbroken text no longer wraps. Moderate confidence.

## Decisions

- One bugfix plan for the three defects, not incident maintenance: the reset
  fix is in the package's generator and changes every project's mockups
  (Sandy, 2026-10-17).
- The test-side refinements (start = left; no size comparison of a box the
  mockup gave its own words) stay in storybook-components' Maintenance.

## Open Questions

- Whether the reset belongs in the generator (every component's stylesheet
  carries the preflight rules it relies on) or in each component (explicit
  colour and font classes). The ADR-less bugfix decides it in the impl.
