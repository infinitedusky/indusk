## Does the impl build what each promise claims, and nothing it does not?

- .indusk/planning/a-run-can-be-trusted/impl.md:370 — the liveness rule calls `isOwnProcess(record.pid, markers, deps, record.startedAt)`, and the record's pid is the admin daemon's `process.pid` (impl.md:382). `isOwnProcess` requires the process's start time to fall within 5 s of `startedAt` (`apps/indusk-mcp/src/lib/process-identity.ts:47-53`), but `startedAt` is when the run started, not when the daemon started. Any run started more than 5 s after the daemon booted reads "stopped — the run's process is gone" while it is running. Because `startBuild` will now refuse only on `runStatus === "running"` (impl.md:388), a second build of the same plan is allowed. The unit rows A9 and A10 inject a start time that matches, so they never see this.
  - breaks when: the admin has been up for minutes, Build is pressed, and the next page load shows the live build as dead and lets Build start a second concurrent run on the same plan.
  - answer: fix — impl.md Decision 4 and Build Phase 1 now record the step session's own `claude` child (pid, program, start time from the session manager's record via a new `onSession` callback) and judge it with `isOwnProcess`, never the daemon's pid; A9/A10 reworded and new A73 (impl and test-plan) starts a real child and checks it running, then stopped.
- .indusk/planning/a-run-can-be-trusted/impl.md:29 — a release reads released, and Build Phase 2's situation reads "complete", when "the plan's branch tip is an ancestor of the trunk" (also impl.md:452, impl.md:464). `plans land` deletes the branch (`land.ts:110`), so after a real landing the check has no ref and the plan reads stopped with "the release ended but the plan is not on main". The reverse also fails: a plan branch just made from main with no commits of its own is already an ancestor, so it reads complete and green.
  - breaks when: `audit-concerns-are-answered` lands cleanly and its page reads stopped, and any freshly started plan whose branch has no commits yet reads complete.
  - answer: fix — impl.md Decision 6, the landed-check and complete tasks now read landed only from the `Merge plan/<plan>: <plan> landed` merge or the archive folder on main, never containment; A21 covers a deleted branch and new A87 (impl and test-plan) a fresh branch with no commits reading not complete.
- .indusk/planning/a-run-can-be-trusted/impl.md:482 — the signals for `shows-where-it-is` (the controls name the plan's real phase), `says-what-is-true` (impl.md:494, the words match the record and files) and `never-in-progress-when-idle` (impl.md:406) each compare what is shown with the function that produced it.   - answer: fix — impl.md Decision 17 and the three signal tasks now judge against raw sources: `shows-where-it-is` against the phase the live step session works, `says-what-is-true` and `never-in-progress-when-idle` against the process table matched to the session manager's held sessions and against `git log` of the trunk, with no call to `situation()`, `shownPhase` or the run record.

- .indusk/promises/a-brief-is-accepted-on-current-main.md:15 — `a-conflict-refuses` is a split clause that reports only when an acceptance actually meets a merge conflict. A clause holds only once its signal has reported upheld in a real run. `the-two-landed-plans-report` says the three clauses report "so that plan can close", but unattended acceptances on current main rarely conflict, so that report may never come.
  - breaks when: no acceptance conflicts in the weeks after landing, `confirm a-brief-is-accepted-on-current-main` keeps finding `a-conflict-refuses` at no-signal, and the plan stays open.
  - answer: fix — impl.md Decision 10 and L2 (impl and test-plan): after landing, one real conflicting acceptance is made on a scratch plan before the confirm, so the clause reports from a real run instead of waiting on chance.

On a loaded machine vitest kills the test before the wait rule can either find the incident or name the break.
  - breaks when: a scan under load takes more than about two and a half minutes after startup, and the landing fails with a vitest timeout instead of a pass.
  - answer: fix — impl.md Decision 12 and Build Phase 6: the upper bound is one exported constant (4 minutes) and the test's vitest timeout is derived from it plus the setup and pause margin, so vitest never ends the test before the rule decides.
- .indusk/planning/a-run-can-be-trusted/impl.md:213 — A59 starts one CPU busy loop per core for the recorder test's duration, and the file gains a `clause:` header, so `plans land`'s clause-test runner (`land.ts:89`) runs it at this plan's landing and at any later landing whose plan's rows name the file.   - breaks when: this plan lands while another plan's landing runs its timed tests, and that other landing fails under the load this test created.
  - answer: fix — impl.md Test Phase 1's recorder task, Decision 12 and A59 (impl and test-plan): the delayed-scan case pauses the admin daemon with SIGSTOP past the old minute and resumes it, adding no CPU load to other landings; the per-core busy loops are gone.
