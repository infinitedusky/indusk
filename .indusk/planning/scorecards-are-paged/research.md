# Scorecards are paged — Research

Cut from `admin-pages-load-fast` on 2026-10-20 so that plan could close with its speedup (Sandy: "make that cut, just get it closed as fast as possible"). These are the eight Build Phase 3 items that were still open when it closed: the scorecards paging the person asked for (q-5) and seven fixes its cold audit found. Each was answered "fix" in `admin-pages-load-fast`'s `audit.md`; this plan is where those fixes land.

## Open items, as written in `admin-pages-load-fast`'s impl

1. **Show the scorecards page 25 at a time**, newest first, with controls to reach older and newer pages; the header reads "N scorecards". Replaces `SCORECARDS_SHOWN = 100` in `apps/indusk-admin/src/app/p/[project]/scorecards/page.tsx` with 25 per page and a `?page=` search parameter. Needs a look (`scorecards.paged`) with a mockup drawn and approved. The once-per-change parse stays.
2. **Make the page-timing measure time every page**, take the slowest of its loads, and fail a page that answers with an error. `apps/indusk-admin/scripts/measure-pages.mjs`: list the root page, `app/new/*`, research, draft and the plan document page (find a parameter for each from the planning folder instead of dropping the route); judge the slowest of the runs, not the median; a status other than 200 fails the page; a cold load waits past `STALE_FOR_MS` (60 s), not 9 s.
3. **Count the process-list and trunk-history reads a page really makes**, instead of reporting one of each. `apps/indusk-admin/src/lib/page-reads.ts:131` sets `processReads` and `landingReads` to constants. Count them from the counted starter (`countStarts` in the package's `start-program.ts`) for the page's async context, so `judgePageReads` can see a second read.
4. **Make the reuse signal notice a page that reads fresh inside the window**, and judge a reading's age against the window that reuse used. `apps/indusk-mcp/src/lib/run-record/kept-reads.ts:109`: `refreshedEarly` can only be true on a backwards clock. Record the last fresh read time per key in the shared slot apart from the entry, and set the flag when a fresh read starts inside the window of the previous one. Report the window reuse used (`max(stored, caller)`) to `page-reads-signal.ts:64`, so a project with `admin.refresh_ms` over the stored window does not read broken.
5. **Put the brief page, the document page and the project home on the page's reads**, and have the recorder find the daemon without a synchronous process start. Those three pages never call `startPage`, so `onThisPage` (`apps/indusk-mcp/src/lib/telemetry/status.ts:154`) hands them the synchronous `realDaemonReads`. `markIncidentVerdict` (`apps/indusk-mcp/src/lib/promises/incident-signal.ts:56`) moves to `commandTracerAsync`. The no-synchronous-starts scan also asserts every page route under `app/p/` calls `startPage`.
6. **Check the remembered repository of a folder is still right before answering from it.** `apps/indusk-mcp/src/lib/worktree/layout.ts:84` `gitCommonDirOf` caches every positive answer for the process's life. Keep with each entry the size-and-time signature of the folder's `.git` entry (one `stat`, no program) and drop the entry when it differs.
7. **File the page-speed reports under the project that declares the page-speed promise**, whichever project's page was shown. `apps/indusk-mcp/src/lib/run-record/page-reads-signal.ts:115` writes with `root` set to the shown project, so a `seat-holds` page's report is stamped with a project that has no `admin-pages-load-fast`. Write it under the admin's own project root and keep the shown project as an attribute.
8. **Keep the admin's remembered readings in one machine-wide place per server**, so an approval clears the copy the pages read. `standingKept` (`standing-kept.ts:25`), `planKept` (`planning-reader.ts:335`), `keptScorecards`, `registryKept` (`registry.ts:521`) and `countsKept` (`overview.ts`) use module-level maps; move each to a `globalThis` `Symbol.for` slot so `resetStandingKept()` in the looks approve route clears the pages' copy.
9. **An approval's reset must not be undone by a refresh already running.** Found by `admin-pages-load-fast`'s falsification; same claim as item 8. `standingKept` (`apps/indusk-admin/src/lib/standing-kept.ts`) stores `held.set(key, …)` when its read finishes and deletes `inFlight` in `finally`, with no check that `resetStandingKept()` ran meanwhile. A refresh started before an approval finishes after the reset and writes the pre-approval standing back for up to 60 s; its `finally` can also delete a newer in-flight read started after the reset. `keptRead` already guards this with a per-entry token (`map.get(key) === next`); give `standingKept` the same guard (a generation number bumped by the reset), with a row that resets mid-read and asserts the old rows are not served.

## Duplication left by `admin-pages-load-fast`'s cleanup

Two read caches do the same job with different rules: `keptRead` (`apps/indusk-mcp/src/lib/run-record/kept-reads.ts`, a time window, a `globalThis` slot, a token guard) and `standingKept` (`apps/indusk-admin/src/lib/standing-kept.ts`, serve-the-last-answer for 60 s, module-level maps, no guard). Five more kept maps sit beside them (`planKept`, `keptScorecards`, `registryKept`, `countsKept`, and `standingKept`'s own). Extraction waited because `plan-state-is-a-database` replaces most plan-state reads; after it lands, whatever is still cached should go through one kept-reading primitive, which also settles items 8 and 9.
