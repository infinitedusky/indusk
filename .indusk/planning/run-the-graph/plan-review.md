  - Build Phase 2 changes `liveness.ts`, which carries `clause: a-run-is-read-from-its-record/dead-reads-stopped`, and no signal task for that clause exists in this plan.

  - answer: fix — the rule is dropped (Sandy's decision): adr.md D6 step 3 and a dated decision in test-plan.md `every-phase-is-checked`, impl.md Build Phase 4 check task, T26 and A35 (now: a test phase whose rows name clauses signalled in later phases joins). ## Which skip reason would you not accept?

- .indusk/planning/run-the-graph/test-plan.md:77 — I would not accept the "no span sees the refusal; … the `ready-phases-start` tick span names its dependents ready late" reason. The same reasoning appears at test-plan.md:36 (the hook's reader disagreeing with the package's) and test-plan.md:173 (a row that is red by design blocking Test Phase 1's join). The tick span defines a phase as ready only once its last dependency's work is on the plan's branch (test-plan.md:48). A phase that never closes or never joins therefore never makes its dependents ready, so the span can never call them late.
  - breaks when: the hook wrongly refuses an independent phase's ticks, or the join wrongly counts a red-by-design row as a failure. No signal reports it; the only trace is a phase stopped after three attempts with a generic reason, and for a phase with no dependents there is nothing at all.
  - answer: fix — test-plan.md lines 36, 77 and 173 replaced: the gate hook now records each refusal in a phase session with the phase that blocked it (impl.md Build Phase 1 new task, T43), and the `no-needless-wait` signal judges each refusal against its own plain dependency scan; the `green-before-merging` signal now judges every join refused as red from its report, and a refusal whose only failures are red by design is broken whether or not the phase has dependents (impl.md Build Phase 4 signal task).

## Which way could a clause fail that no signal would see?

- .indusk/planning/run-the-graph/impl.md:649 — the `ready-phases-start` signal takes a phase's launch time from its branch's creation in the reflog. The branch is cut before `provisionWorktree` (the install, impl.md:451) and before `startSession`, and one pass runs its starts one after another (impl.md:601). A session that actually starts minutes after its branch was cut reads as launched on time. Only the fifteen-minute "branch with no session" rule would ever see the gap.
  - breaks when: the install is slow (cold cache, a large lockfile), or one pass starts several phases, so a session starts more than a minute after it was ready while the cap had room.
  - answer: fix — test-plan.md `ready-phases-start` signal and a new fails-when line, impl.md Build Phase 5 signal task: the launch time is now the phase session's own `startedAt` in the session manager's sessions file, read after each start and at each tick and kept in the signal's log, never the branch's reflog entry.
